Exercices 1.11
01
l'idée

Un pointeur n'est pas une valeur : c'est une adresse

La définition du cours tient en une ligne : un pointeur est une variable qui contient l'adresse d'une autre donnée — une variable, un tableau, une structure, une fonction, ou même un registre du matériel.

À retenir

Une variable ordinaire est une boîte avec une étiquette et une valeur. Un pointeur est une boîte qui contient le numéro d'une autre boîte. Le papier sur lequel tu écris « 0x1000 » n'est pas la maison : il te dit seulement où aller. Deux papiers peuvent porter la même adresse, et déchirer un papier ne démolit pas la maison.

Pourquoi le C en a besoin

Le cours donne trois raisons, et elles couvrent tout le reste :

  • Retourner un résultat par une fonction — une fonction ne renvoie qu'une valeur avec return ; avec une adresse, elle peut remplir plusieurs cases de l'appelant.
  • Créer et traiter des objets dynamiquement — la taille d'un tableau n'est pas toujours connue à la compilation ; malloc rend une adresse, pas une boîte.
  • Accéder aux registres du matériel — un registre n'a pas de nom en C, seulement une adresse. On écrit *(volatile uint32_t *)0x40000000 = 1; et la carte répond.
Le vocabulaire du cours

Pointeur : la variable qui contient l'adresse. Cible ou objet pointé : la donnée à cette adresse. Déréférencement : lire ou écrire la cible à travers le pointeur. Pointeur nul : NULL, l'adresse « aucune » — on ne la déréférence jamais.

Le piège

« Un pointeur, c'est la valeur » : non. Si x = 42 et p = &x, alors p ne vaut pas 42, il vaut 0x1000. Et *p vaut 42. Confondre les deux, c'est confondre le numéro de la maison avec le contenu du salon.

02
la mémoire

La mémoire est un ruban d'octets numérotés

Chaque octet a une adresse. Une variable occupe sizeof(type) octets consécutifs, et son adresse est celle de son premier octet. Un pointeur n'est qu'un nombre de ce ruban, rangé dans une case de ce même ruban.

Sur une machine 64 bits, un int occupe 4 octets et un pointeur 8. Sur une machine 32 bits, le pointeur occuperait 4 octets. C'est pour cela qu'on n'écrit jamais « un pointeur fait 4 octets » : on écrit sizeof(int *).

clique sur une variable pour voir ses octets
interactif
Clique sur x, c ou p : la case mémoire s'allume et le détail s'affiche ici.

Dans l'explorateur, x vaut 42 et p contient l'adresse de x, 0x1000. Les quatre octets de x sont 2A 00 00 00 : c'est du petit-boutisme (little endian), l'ordre utilisé par x86 et ARM. La valeur se lit à l'envers : 0x0000002A = 42.

La règle

&x a le type int * et vaut l'adresse du premier octet de x. &x + 1 ne vaut pas « l'octet suivant » : l'arithmétique des pointeurs avance par pas de sizeof(*p), donc de 4 octets ici.

Deux confusions classiques

sizeof(p) donne la taille du pointeur (8), pas celle de la cible. Pour la cible, écris sizeof(*p). Et sizeof(a) pour un tableau donne la taille du tableau (4 × 4 = 16), sauf dans une fonction où a est devenu un pointeur.

Pour les embedded

Un registre matériel est une adresse comme une autre, mais le compilateur ne doit pas optimiser les accès : on le déclare volatile. volatile uint32_t * const pReg = (uint32_t *)0x40000000; puis *pReg = 1u; — le pointeur est constant, la cible est volatile.

03
les deux gestes

Deux gestes : & prend l'adresse, * accède à la valeur

&x fabrique l'adresse de x. *p lit ou écrit la case dont p contient l'adresse. Le premier geste part d'une variable ; le second part d'un pointeur. Tout le reste du chapitre n'est que la combinaison de ces deux-là.

dereferencement.c
char var1 = 'A';
char *pVar = &var1;   /* pVar reçoit l'adresse de var1 */
*pVar = 'B';          /* écrire à cette adresse, c'est écrire dans var1 */
printf("%c\n", var1); /* affiche B */

La règle des deux étoiles

Dans une déclaration, * appartient au type : int *p se lit « p est un pointeur vers int ». Dans une expression, * est un opérateur : *p se lit « la valeur à l'adresse p ». Même symbole, deux grammaires différentes.

Ce qui provoque un comportement indéfini

Déréférencer NULL ; déréférencer un pointeur non initialisé (il contient une adresse quelconque) ; déréférencer un pointeur après free ; déréférencer un pointeur vers une variable locale qui n'existe plus. Dans tous ces cas, le compilateur ne dit rien : c'est le programme qui casse, parfois loin de la faute.

Afficher une adresse

printf("%p\n", (void *)p); — le format %p attend un void *, d'où le cast. %d sur un pointeur est une erreur de format : le comportement n'est pas défini.

04
lire un type

Lire une déclaration sans se tromper

La difficulté du C n'est pas le pointeur, c'est sa déclaration. Une étoile, des crochets et des parenthèses peuvent décrire un tableau de pointeurs ou un pointeur vers un tableau — et ce n'est pas la même chose. La bonne nouvelle : une seule règle suffit.

La méthode

Pars du nom, va vers la droite en lisant [] (tableau) et () (fonction), puis remonte vers la gauche en lisant * (pointeur). Les parenthèses forcent la priorité, exactement comme en arithmétique. int *p[5] : p, puis [5] → tableau de 5, puis * → de pointeurs vers int.

anatomie.c
int   *   p   =   &x;
/*  ↑   ↑   ↑       ↑
    |   |   |       └── l'adresse d'un int (type int *)
    |   |   └────────── le nom de la variable
    |   └────────────── « pointeur vers »
    └────────────────── le type de la cible                     */

Cette anatomie explique pourquoi int *p et int* p sont identiques pour le compilateur : l'espacement ne change rien. Ce qui change tout, c'est l'endroit de l'étoile par rapport aux crochets et aux parenthèses.

Le piège de la virgule

int* a, b; ne déclare pas deux pointeurs : a est un int *, b est un int. L'étoile se colle à la variable, pas au type. Écris une déclaration par ligne, ou utilise un typedef.

typedef.c
typedef int *IntPtr;   /* IntPtr est un type : pointeur vers int */
IntPtr a, b;           /* a et b sont deux pointeurs        */

typedef int (*BinOp)(int, int);  /* pointeur de fonction, lisible */
BinOp op = add;
Le pointeur générique

void *p peut contenir l'adresse de n'importe quel objet. On ne peut pas le déréférencer tel quel : il faut d'abord le convertir, *(int *)p. C'est le type de retour de malloc, et le type des callbacks de qsort.

05
le simulateur

Sept lignes, sept états mémoire

Voici le programme minimum qui contient tout : déclarer, pointer, écrire à travers le pointeur, relire la variable, puis casser volontairement le pointeur. Avance ligne par ligne : la case qui change clignote, la flèche apparaît et disparaît.

Simulateur · x, p et *p
clique sur une ligne ou utilise les boutons
8 états
    Sortie—
    Le point clé

    x et *p désignent le même octet. Écrire dans l'un, c'est écrire dans l'autre. En revanche, p et *p sont deux objets différents : p est une case de 8 octets à 0x2000, *p est la case de 4 octets à 0x1000.

    Modifier le pointeur ou la cible ?

    p = NULL; change le pointeur (la flèche). *p = 0; change la cible (la valeur au bout de la flèche). Les deux s'écrivent presque pareil et n'ont rien à voir. C'est la question numéro un des QCM.

    Le pointeur a lui aussi une adresse, une taille et une durée de vie. &p est de type int ** et vaut 0x2000 dans le simulateur. Cette adresse ne change pas tant que p existe ; seule sa valeur change quand on le réaffecte.

    06
    tableaux

    Un tableau est un bloc contigu

    Les éléments d'un tableau int a[4] sont rangés côte à côte, sans trou : 4 octets chacun. Le nom a désigne le premier élément dans une expression. De là vient l'équivalence a[i] == *(a + i), et toute l'arithmétique des pointeurs.

    tableau.c
    int a[4] = {10, 20, 30, 40};
int *p = a;              /* identique à &a[0] */

printf("%d\n", a[2]);    /* 30 */
printf("%d\n", *(a+2));  /* 30 : exactement la même chose */
printf("%d\n", *(p+2));  /* 30 : p pointe sur a[0] */
printf("%d\n", p[2]);    /* 30 : p[i] est permis aussi */
    La règle d'or

    a[i] est défini comme *(a + i). L'addition est commutative, donc *(a+i) == *(i+a), et i[a] est légal (mais illisible). p[i] marche aussi : un pointeur n'a pas besoin d'être un tableau pour être indexé, il suffit qu'il pointe sur un bloc assez grand.

    Le pas de l'addition dépend du type pointé, pas de la valeur. p + 1 ajoute sizeof(*p) octets : 4 pour un int *, 1 pour un char *, 8 pour un double *. C'est le compilateur qui fait la multiplication ; toi, tu écris seulement + 1.

    Trois pièges d'examen
    • sizeof(a) contre sizeof(p) : 16 contre 8 ici. Dans une fonction, a reçu en paramètre est un pointeur : sizeof(a) vaut 8, et sizeof(a)/sizeof(a[0]) vaut 2, pas 4. Il faut passer la longueur séparément.
    • &a contre a : même adresse, types différents. a + 1 avance de 4 octets ; &a + 1 avance de 16 octets, car le type est int (*)[4].
    • Un-past-end : a + 4 est permis pour comparer ou calculer une fin de boucle, mais *(a + 4) lit hors du tableau : comportement indéfini.

    *p++, (*p)++, *++p : le tableau des priorités

    Le suffixe ++ est plus prioritaire que l'étoile ; le préfixe ++ et l'étoile ont la même priorité et s'associent de droite à gauche. D'où quatre effets différents qu'il faut savoir lire instantanément :

    Tableaux à deux dimensions

    int m[3][4] est un tableau de 3 tableaux de 4 int, contigus. Dans une expression, m se convertit en int (*)[4] (pointeur vers une ligne) ; m[i] est un tableau de 4 int qui se convertit en int * vers le premier élément de la ligne. Et m[i][j] == *(*(m + i) + j). Un pointeur de ligne s'écrit int (*ligne)[4] = m; : ligne + 1 saute 16 octets.

    07
    chaînes

    Chaînes : un tableau et un pointeur ne sont pas la même chose

    En C, une chaîne n'est pas un type : c'est une suite de char terminée par l'octet nul '\0'. On peut la ranger dans un tableau (une copie modifiable) ou pointer vers un littéral (souvent en lecture seule). Les deux s'écrivent presque pareil et se comportent très différemment.

    chaines.c
    char s[] = "abc";       /* 4 octets : 'a','b','c','\0' — copie modifiable */
char *t  = "abc";       /* pointeur vers un littéral : lecture seule     */

s[0] = 'x';             /* OK : s est un tableau                          */
/* t[0] = 'x'; */       /* UB : le littéral n'est pas modifiable          */

t = s;                  /* OK : t pointe maintenant vers le tableau s     */
printf("%zu %zu\n", sizeof(s), sizeof(t));  /* 4 puis 8              */
    Les trois tailles

    sizeof(s) = 4 (le tableau, terminateur compris) ; strlen(s) = 3 (sans le terminateur) ; sizeof(t) = 8 (le pointeur). strlen compte les octets jusqu'au premier '\0' : si le terminateur manque, elle continue dans la mémoire voisine.

    Le tableau trop court

    char s[4] = "abcd"; est légal en C, mais le '\0' n'a pas de place : strlen(s) lit au-delà du tableau. Prévois toujours strlen + 1. Et char *t = "abc"; ne copie rien : c'est un pointeur vers un bloc que tu n'as pas le droit de modifier.

    Le lien avec argv

    int main(int argc, char *argv[]) : argv est un tableau de pointeurs vers char. argv[i] est un char * (une chaîne), argv[i][0] est son premier caractère, et argv[argc] vaut NULL par convention. C'est exactement le même mécanisme que char **.

    08
    structures

    Structures : p->x est un raccourci pour (*p).x

    Un pointeur de structure est le cas le plus fréquent en C : les listes, les arbres, les tampons et les registres embarqués en sont pleins. La flèche -> n'est pas un opérateur magique : elle déréférence puis accède au membre, en un seul geste.

    Pourquoi les parenthèses

    L'opérateur . est plus prioritaire que *. Donc *p.x se lit *(p.x) : on cherche un membre x dans le pointeur, ce qui n'a pas de sens. Pour atteindre le membre, il faut (*p).x — ou, par définition, p->x.

    Copie ou pointeur ?

    struct Point q = pt; copie les 8 octets : modifier q.x ne touche pas pt.x. Passer une structure à une fonction par valeur la copie aussi. Pour les grosses structures, on passe const struct Point *p : pas de copie, et la lecture seule est garantie.

    Le bourrage

    sizeof(struct { char c; int i; }) vaut souvent 8, pas 5 : le compilateur insère 3 octets de bourrage pour aligner i sur 4 octets. Ne calcule jamais la taille d'une structure en additionnant ses membres ; utilise sizeof, et offsetof pour localiser un champ.

    09
    fonctions

    Passage par valeur : l'adresse est la seule façon de modifier l'appelant

    En C, tous les arguments sont passés par valeur : la fonction reçoit une copie. Pour modifier la variable de l'appelant, il faut lui donner son adresse — et c'est le pointeur qui fait le travail. Le swap est l'exemple canonique, et le cours le montre avec quatre variantes.

    Laboratoire · le swap qui échoue, le swap qui réussit
    deux cadres de pile, deux stratégies
    11 étapes
    swap.c
    void swap_bad(int a, int b) { int t = a; a = b; b = t; }        /* copies */
void swap_ok (int *a, int *b) { int t = *a; *a = *b; *b = t; }  /* adresses */

int main(void) {
    int x = 1, y = 2;
    swap_bad(x, y);      /* x = 1, y = 2 : rien ne change */
    swap_ok(&x, &y);    /* x = 2, y = 1 : ça marche       */
}
    La règle

    Le C ne connaît que le passage par valeur. « Passage par référence » est une façon de parler : on passe une adresse, donc une valeur de type pointeur, et la fonction utilise * pour atteindre l'original. scanf("%d", &x) fonctionne exactement comme swap_ok : scanf a besoin de l'adresse pour écrire dans x.

    Le pointeur aussi est copié

    Dans void f(int *p), le paramètre p est une copie du pointeur de l'appelant. *p = 3 modifie la cible, mais p = NULL ne change que la copie locale. Pour modifier le pointeur de l'appelant, il faut passer son adresse : void f(int **pp). C'est le sujet de la section suivante.

    Renvoyer un pointeur : la question de la durée de vie

    Une fonction peut renvoyer un pointeur, mais la cible doit vivre plus longtemps que l'appel. Trois cas seulement sont sûrs : un objet static ou global, un bloc alloué par malloc, ou un objet de l'appelant passé en argument. Renvoyer l'adresse d'une variable locale est l'erreur classique : la pile est réutilisée dès le retour.

    retour.c
    int *bad(void)  { int local = 42; return &local; }     /* suspendu : interdit */
int *good(void) { static int local = 42; return &local; } /* durée de vie du programme */
int *heap(void) { return malloc(sizeof(int)); }           /* à free plus tard      */
    Tableaux en paramètre

    void f(int a[10]) et void f(int *a) déclarent exactement la même chose : un pointeur. La taille 10 est ignorée. sizeof(a) vaut 8 dans la fonction, et le compilateur ne peut pas détecter un débordement. Passe toujours size_t n avec le tableau.

    10
    pointeur de pointeur

    int ** : pour modifier le pointeur de l'appelant

    Un pointeur de pointeur n'est pas un monstre : c'est un pointeur dont la cible est elle-même un pointeur. Il sert dès qu'une fonction doit changer l'adresse contenue dans le pointeur du caller — allocation, insertion en tête de liste, tableau de chaînes.

    Laboratoire · deux, puis trois niveaux
    chaque étoile ajoute un saut
    6 étapes

    Le cas d'usage du cours est l'allocation dans une fonction. Si la fonction reçoit int *p, elle reçoit une copie du pointeur : p = malloc(...) ne change rien chez l'appelant. Si elle reçoit int **pp, elle reçoit l'adresse du pointeur et peut écrire dedans avec *pp = malloc(...).

    allouer.c
    /* reçoit l'adresse du pointeur : peut le modifier */
void allouer(int **pp, int valeur)
{
    *pp = malloc(sizeof **pp);
    if (*pp != NULL) {
        **pp = valeur;
    }
}

int *p = NULL;
allouer(&p, 42);       /* *p vaut maintenant 42 */

/* variante qui échoue : p est une copie */
void allouer_bad(int *p) { p = malloc(sizeof *p); }  /* fuite + p inchangé */
    Ne confonds pas les types

    int **pp n'est pas « un tableau d'int » ni « un int * ». C'est un pointeur vers une case qui contient un int *. Le nombre d'étoiles est le nombre de sauts à faire pour atteindre l'objet final. char **argv s'utilise comme un tableau de pointeurs vers char ; char *argv[] est la même chose dans une liste de paramètres.

    Applications

    Listes chaînées : void insert(Node **head, ...) pour modifier la tête. Tableaux de chaînes : char **noms. Matrices dynamiques : int **m avec une allocation par ligne. Structures : struct tm ** pour modifier un pointeur de structure. À chaque fois, la question est : « est-ce que je veux changer la cible, ou le pointeur lui-même ? »

    11
    const

    const : trois contrats, pas un seul

    const ne rend rien immuable à l'exécution : c'est une promesse au compilateur. Sa place par rapport à l'étoile décide de ce qui est protégé — la cible, le pointeur, ou les deux. Les trois combinaisons se rencontrent partout dans les en-têtes de fonctions.

    La lecture qui marche à tous les coups

    Lis de droite à gauche : const int *p → « p est un pointeur vers un int const ». int *const p → « p est un pointeur const vers un int ». const s'applique à ce qui est juste à sa gauche ; s'il n'y a rien à gauche (ou seulement le type de base), il s'applique à droite. const int *p et int const *p sont identiques.

    Où l'utiliser

    Pour les paramètres que la fonction ne modifie pas : void afficher(const char *s), void dump(const struct tm *pt). Pour les pointeurs globaux constants : volatile uint32_t *const pReg. Pour les tableaux de chaînes : const char *const noms[] — un tableau de pointeurs constants vers des chaînes constantes.

    Le piège du cast

    const est une protection de compilation, pas un verrou matériel. Si tu retires le const par un cast et que tu écris dans une zone réellement en lecture seule, c'est un comportement indéfini. Et un pointeur const doit être initialisé à la déclaration : on ne peut plus lui donner d'adresse après.

    12
    pile & tas

    malloc rend une adresse, pas une variable

    Les variables locales vivent sur la pile : leur durée de vie est le bloc, et le compilateur gère tout. Les objets de durée de vie inconnue vivent sur le tas : c'est toi qui demandes la place avec malloc, et c'est toi qui la rends avec free. Un pointeur est le seul lien entre les deux mondes.

      Le cast de malloc

      En C, le cast n'est pas nécessaire : void * se convertit implicitement vers tout pointeur d'objet. Le cours écrit parfois (int *)malloc(...) ; les deux compilent, mais le cast est obligatoire en C++ et peut masquer un oubli d'inclusion en C. Préfère int *p = malloc(sizeof *p);.

      Les quatre fautes qui coûtent le plus
      • Fuite : p = malloc(...); p = NULL; sans free — le bloc est perdu.
      • Pointeur suspendu : free(p); *p = 1; — usage après libération, comportement indéfini.
      • Double free : free(p); free(p); — le tas est corrompu. Mettre p = NULL après le premier free.
      • Libération d'une adresse qui n'est pas du tas : free(&x) ou free(p + 1) — interdit.
      Pile ou tas ?

      Pile : variables locales, paramètres, adresses de retour. Allocation instantanée, libération automatique à la fin du bloc, taille limitée. Tas : malloc/free, durée de vie contrôlée, fragmentation possible, plus lent. Une variable globale ou static vit ni sur l'un ni sur l'autre : elle a une durée de vie égale au programme.

      pointeur de fonction

      Un pointeur peut viser du code

      Une fonction a une adresse, elle aussi. Un pointeur de fonction stocke cette adresse et permet d'appeler la fonction choisie à l'exécution : table de dispatch, callbacks, comparateurs de qsort. C'est la dernière pièce du chapitre, et elle explique les callbacks du cours d'embarqué.

      clique sur add ou mul
      interactif

      0x401000
      int (*)(int, int)

      fonction_pointeur.c
      int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

/* déclaration : parenthèses obligatoires autour de *op */
int (*op)(int, int) = add;     /* op contient l'adresse de add */

int r1 = op(3, 4);             /* 7  : appel direct              */
op = mul;                      /* op contient maintenant mul     */
int r2 = op(3, 4);             /* 12                             */

/* la version lisible */
typedef int (*BinOp)(int, int);
BinOp f = &mul;                 /* & est facultatif             */
int r3 = (*f)(3, 4);           /* 12 : (*f) est aussi permis      */
      La syntaxe en une phrase

      int (*op)(int, int) : « op est un pointeur vers une fonction prenant deux int et renvoyant un int ». Sans les parenthèses, int *op(int, int) est une fonction qui renvoie un int *. Les parenthèses changent la nature de la déclaration, pas seulement le style.

      Table de dispatch

      Un tableau de pointeurs de fonction remplace une longue chaîne de if :

      BinOp ops[] = {add, mul};
int r = ops[choix](3, 4);   /* choix vaut 0 ou 1 */
      Callbacks

      qsort reçoit un comparateur int (*)(const void *, const void *) ; un bouton reçoit un handler ; une machine à états reçoit une table de fonctions. Dans tous les cas, la fonction appelante ne connaît pas le nom de la fonction à exécuter : elle connaît seulement son adresse.

      Le piège de la déclaration

      int *f(int) : fonction qui renvoie un pointeur vers int. int (*f)(int) : pointeur vers une fonction qui prend un int. Le cours montre aussi une fonction qui renvoie un pointeur de fonction : Function_t getfct_p(int16_t param); — le typedef rend cette déclaration lisible.

01
définition

Un algorithme : une suite finie d'opérations non ambiguës

Les diapositives du cours donnent deux définitions : « une suite finie et non ambiguë d'opérations ou d'instructions permettant de résoudre un problème ou d'obtenir un résultat » (Wikipédia), et « une suite d'actions que devra effectuer un automate pour arriver, en un temps fini, à un résultat déterminé », d'une précondition à une postcondition (Courtin et Kowarski).

À retenir

L'algorithme est la recette, le programme n'est qu'une de ses écritures. La même boucle se lit en pseudocode, se dessine en diagramme de flux ou en Nassi-Shneiderman, puis se code en C : quatre représentations, une seule logique.

Les critères du cours : trois indispensables, un souhaité

finitudes'arrête-t-il pour toute entrée valide ?for (int i = 0; i < n; i--) : la condition reste vraie

La diapositive 7 résume la démarche en trois temps : analyser la fonctionnalité, la décomposer sur papier, puis planifier l'implémentation. Chaque étape reste indépendante du langage.

La démarche

Pour l'exercice 1.3 : la fonctionnalité est « afficher chaque fruit et sa première lettre en majuscule » ; la décomposition donne une boucle, une lecture d'un caractère, un test de minuscule, un masque, un affichage ; l'implémentation tient dans une seule boucle.

Le piège

Un algorithme qui boucle n'est pas un algorithme. La finitude ne se constate pas en exécutant : elle se prouve en montrant quelle variable avance vers la condition d'arrêt. Un corps de boucle qui ne modifie pas la variable testée ne s'arrête jamais, même s'il compile.

Quel critère indispensable manque à for (int i = 0; i < n; i--) ?
La finitude. i part de 0 et décroît ; i < n reste vrai pour tout n positif, donc la boucle ne s'arrête jamais. Le déterminisme et les entrées/sorties ne sont pas en cause.
02
pseudocode

Trois constructions suffisent : séquence, sélection, itération

Le pseudocode écrit l'algorithme dans une langue lisible, sans la syntaxe du C. Il garde trois constructions et une règle : chaque bloc imbriqué est indenté. La diapositive 8 du cours dessine ces trois constructions et étiquette la décision cond_expr? avec deux sorties, true et false.

Les conventions retenues
  • ← pour l'affectation, = pour la comparaison : la confusion est la première erreur.
  • Un bloc par ligne, quatre espaces d'indentation ; chaque bloc ouvert est fermé (fin si, fin tant que, fin pour).
  • Les identifiants gardent la forme du cours : camelCase et préfixe c pour les constantes (cMyfruits, cNbrOfFruits), e pour les énumérations (eNameLen).
  • Une décision s'écrit avec deux issues explicites, jamais avec une condition composée non parenthésée.
  • Les commentaires commencent par // ou /* … */, comme en C.
Le piège

'a' <= c <= 'z' se lit ('a' <= c) <= 'z' : la comparaison rend 0 ou 1, et 1 est toujours inférieur à 'z'. L'expression est vraie pour '3' comme pour 'o'. Il faut écrire (c >= 'a') && (c <= 'z').

Test avant, test après

while et for testent avant le corps : zéro tour est possible. do … while teste après : au moins un tour, même si la condition est fausse dès le départ. Le diagramme montre la différence par la place du losange.

Combien de tours pour for (int i = 0; i < 0; i++), et pour un do … while de même condition ?
Zéro tour pour le for, un tour pour le do … while : le test du do vient après le corps.
03
diagramme de flux

Le diagramme de flux : cinq symboles, un seul sens de lecture

Un organigramme se lit de haut en bas, comme le programme s'exécute. Chaque forme a un sens fixe ; les flèches portent le contrôle. Un losange a toujours deux sorties, un ovale ne sert qu'à ouvrir et fermer le schéma.

Les cinq symboles employés au cours
symbolesensexemple
ovale — début et fin du programmeun seul ovale de début, un seul de fin
rectangle — traitement : une affectation, un calculi ← 0, firstChar &= ~0x20
losange — décision : une entrée, deux sorties true / falsei < 5 ?, (c >= 'a') && (c <= 'z') ?
parallélogramme — entrée ou sortie de donnéesprintf(…), scanf(…)
connecteur — renvoi à un autre point du schémaévite une flèche qui traverse la page
La règle de lecture

Une flèche par issue, et l'étiquette de l'issue écrite à côté : true / false sur les diapositives, vrai / faux ou oui / non dans les corrigés. Le retour d'une boucle repart vers le losange du test, jamais vers le premier bloc du corps.

Connecteurs

Un connecteur étiqueté A remplace une longue flèche de retour : on ferme la flèche sur un cercle A et on la reprend sur un autre cercle A. Deux connecteurs de même lettre désignent le même point du schéma.

Le piège

Un diagramme incomplet se reconnaît à trois signes : un losange qui n'a qu'une sortie, un bloc qui n'a ni entrée ni sortie, une boucle dont la flèche repart vers le corps au lieu du test. Le schéma doit se lire sans le code à côté.

Peut-on dessiner une boucle sans losange ?
Non : il faut un test pour décider de répéter ou de sortir. Une flèche qui remonte sans condition décrit une répétition infinie, ce qui viole la finitude.
04
nassi-shneiderman

Nassi-Shneiderman : les blocs imbriqués, sans une flèche

Le Nassi-Shneiderman (NS) remplace les flèches par l'imbrication : un bloc contenu dans un autre est répété par lui. Une séquence est une pile de bandes ; une décision est un triangle dont la pointe descend entre deux colonnes, oui à gauche et non à droite ; une boucle est un cadre qui englobe son corps.

Les trois conventions du NS

bouclecadre autour d'un en-tête et du corpsl'en-tête donne le test ; tout ce qui est dans le cadre est répété

La règle

La largeur totale ne change jamais : le triangle occupe toute la largeur, puis se partage en deux colonnes. Une boucle ajoute un cadre à l'intérieur du cadre existant. On lit un NS comme un plan : de haut en bas, puis de gauche à droite dans chaque triangle.

NS ou diagramme de flux

Le NS montre la structure (imbrication) et tient dans un rectangle ; le diagramme de flux montre le trajet et se prête aux retours. Pour un rapport, le NS est plus compact ; pour expliquer un algorithme à quelqu'un qui ne lit pas le code, le diagramme de flux est plus direct.

Le piège

Un bloc placé en dehors du cadre ne se répète pas : c'est l'erreur classique sur l'en-tête ou sur l'initialisation. Dans l'exercice 1.3, char firstChar est déclarée dans le corps : sa portée s'arrête à la fin du tour, et sa valeur ne survit pas d'un tour à l'autre.

Dans le NS ci-dessus, quelle bande s'exécute cinq fois ?
Toutes celles qui sont dans le cadre : la lecture, le triangle, la branche prise et l'affichage. L'en-tête, lui, fixe le nombre de tours ; il n'est pas « exécuté » cinq fois. Les blocs oui et non ne s'exécutent qu'un seul des deux par tour.

table de trace

Table de trace : une ligne par tour, une colonne par variable

La table de trace est l'exécution écrite à la main. Une colonne par variable, une colonne pour la condition testée, une colonne pour ce qui sort à l'écran, et une ligne par exécution du corps — plus une ligne finale pour le test qui échoue.

Trace de factIter(4) : acc ← 1 puis for (i = 2; i <= 4; i++) acc *= i;
touriacceffet

tour 2323 ≤ 4 vrai → acc ← 2 × 3 = 6
tour 3464 ≤ 4 vrai → acc ← 6 × 4 = 24
fin5245 ≤ 4 faux → sortie de la boucle
Les trois colonnes obligatoires
  • variables : une colonne par variable lue ou écrite dans le corps, dans l'ordre de la déclaration.
  • conditions : la valeur du test au moment où il est évalué, pas après le pas suivant.
  • sortie : ce que le programme affiche, recopié exactement, sans arrondi ni reformulation.

Ce que la trace prouve

La trace rend l'erreur visible : un tour de trop se voit dans le nombre de lignes, une valeur fausse se voit dans une colonne, un masque oublié se voit dans la colonne firstChar. C'est le seul contrôle qui ne demande pas d'exécuter le programme.

Le piège

Deux fautes de méthode : noter la valeur d'après le pas i++ au lieu de celle du tour, et oublier la ligne finale du test. Une table sans la dernière ligne laisse croire que la boucle s'arrête « après le dernier tour », sans dire sur quelle valeur.

Combien de lignes pour une boucle de 5 tours qui imprime à chaque tour ?
Cinq lignes de corps, plus la ligne du test final qui échoue : six lignes en tout, et cinq lignes de sortie. La ligne finale ne produit aucune sortie.

exercice 1.3

Exercice 1.3 : cinq fruits, cinq tours, un masque

L'énoncé demande de documenter une boucle for donnée en C par un Nassi-Shneiderman et un diagramme de flux. Le code imprime chaque fruit, puis sa première lettre convertie en majuscule. La conversion tient à un seul opérateur : &= ~0x20.

ex1-3.c — code de l'énoncé, NameLen ajouté
#include <stdio.h>
#include <stdint.h>

enum { NameLen = 16 };      /* l'énoncé utilise NameLen sans le définir */

char const cMyfruits[][NameLen] = {"orange", "apple", "banana",
                                   "mango", "litchi"};
uint16_t const cNbrOfFruits = sizeof cMyfruits / sizeof cMyfruits[0];

int main(void)
{
    for (int i=0; i<cNbrOfFruits; i++)
    {
      char firstChar = cMyfruits[i][0];
      if ((firstChar>='a' ) && (firstChar<='z'))
      {
        firstChar &= ~0x20;
      }
      printf("Fruit %u) is %s - starts with %c\n", i, cMyfruits[i], firstChar);
    }
    return 0;
}
NameLen et sizeof

L'énoncé écrit char const cMyfruits[][NameLen] sans définir NameLen : il faut l'ajouter pour compiler. Avec 16, le tableau occupe 80 octets (5 × 16) et sizeof cMyfruits / sizeof cMyfruits[0] vaut 5 — le nombre de lignes ne dépend pas de NameLen, tant qu'il laisse la place au '\0' de "banana".

À retenir

Le %s affiche orange, le %c affiche O : le masque s'applique à firstChar, une copie d'un caractère, jamais au tableau. C'est pourquoi les noms restent en minuscules dans la même ligne de sortie.

Le masque, bit par bit

En ASCII, 'a' vaut 0x61 et 'A' vaut 0x41 : les deux lettres ne diffèrent que par le bit 5 (0x20). ~0x20 est un int négatif (0xFFFFFFDF, soit −33) ; le ET garde les huit bits utiles et éteint le bit 5, ce qui met une minuscule en majuscule.

La règle du masque

Le test de plage passe avant le masque : sans lui, '3' (0x33) deviendrait 0x13 et '!' (0x21) deviendrait 0x01. Et le masque s'applique à la copie firstChar, pas à cMyfruits[i][0], qui est const.

Le piège

firstChar *= 0x20 multiplie au lieu de masquer ; firstChar | 0x20 force la minuscule ; firstChar -= 0x20 ne marche que pour les lettres dont le bit 5 vaut 1, et abîme les autres. Le masque correct est &= ~0x20 : il éteint le bit, il ne soustrait pas.

Que vaut sizeof cMyfruits[0], et sizeof cMyfruits ?
16 et 80 avec NameLen = 16 : chaque ligne fait 16 octets, le tableau en contient 5. Le quotient vaut 5, quelle que soit la valeur de NameLen (à condition qu'elle contienne "banana" et son '\0').

Trois exemples : algorithme, diagramme, trace

La factorielle (exercice 1.2), le convertisseur (1.6) et la boucle for (1.4) suivent la même chaîne : un énoncé, un algorithme en pseudocode, un diagramme, puis une trace et une sortie vérifiée.

Factorielle : 20! tient dans un unsigned long long

La factorielle de n est le produit des entiers de 1 à n, avec 0! = 1. L'algorithme itératif tient en trois lignes de pseudocode et en un accumulateur.

factorielle.pseudo
fonction factIter(n) : entier long non signé
    acc ← 1
    pour i ← 2 à n faire
        acc ← acc × i
    fin pour
    retourner acc
factorielle.c
#include <stdio.h>

unsigned long long factIter(unsigned n)
{
    unsigned long long acc = 1;
    for (unsigned i = 2; i <= n; i++) {
        acc *= i;
    }
    return acc;
}

int main(void)
{
    for (unsigned n = 0; n <= 20; n++) {
        printf("The factorial of %2u using loop is: %llu\n", n, factIter(n));
    }
    return 0;
}

Convertisseur : 51 tours, de −20 °C à 30 °C

La formule de l'exercice 1.6 est T(°F) = T(°C) × 1,8 + 32. Une fonction isole le calcul, une boucle produit la table, deux constantes fixent les bornes.

convertisseur.c
#include <stdio.h>

enum { eMinC = -20, eMaxC = 30 };   /* les bornes, en constantes */

double celsiusToFahrenheit(double c)
{
    return c * 1.8 + 32.0;
}

int main(void)
{
    printf("Value of %6.2f%cC corresponds to %6.2f%cF\n",
           10.0, (char)0xF8, celsiusToFahrenheit(10.0), (char)0xF8);

    for (int c = eMinC; c <= eMaxC; c++) {
        printf("Value of %+6.1f%cC corresponds to %+6.1f%cF\n",
               (double)c, (char)0xF8, celsiusToFahrenheit(c), (char)0xF8);
    }
    return 0;
}

Le symbole °

L'énoncé propose la valeur 248 (0xF8) pour afficher ° sur la console. C'est exact dans la page de code de la console Windows (CP850 ou CP437, où 0xF8 est U+00B0) ; en UTF-8 ou en Windows-1252, le même symbole n'est pas 248.

Boucle for : afficher le tableau, puis la majuscule

L'exercice 1.4 empile les trois usages : parcours complet du tableau, première lettre en majuscule par masque, puis opérateurs logiques et ternaire. Le tableau et les bornes sont ceux de l'exercice 1.3.

ex1-4.c
/* a) parcourir le tableau et l'afficher */
for (int i = 0; i < cNbrOfFruits; i++)
    printf("%d : %s\n", i, cMyfruits[i]);

/* b) + c) + d) : masque, comparaison et ternaire */
for (int i = 0; i < cNbrOfFruits; i++) {
    char c   = cMyfruits[i][0];
    char maj = ((c >= 'a') && (c <= 'z')) ? (char)(c & ~0x20) : c;
    printf("%-7s %c (0x%02X) -> %c (0x%02X)\n", cMyfruits[i], c,
           (unsigned char)c, maj, (unsigned char)maj);
}

La règle

Le ternaire cond ? si_vrai : si_faux est une expression, pas une instruction : il rend une valeur, ce qui permet d'initialiser maj en une ligne. Le masque reste le même : c & ~0x20, appliqué seulement si le test de plage est vrai.

Pourquoi la boucle du convertisseur fait-elle 51 tours et non 50 ?
Parce que les deux bornes sont incluses : c va de −20 à 30 en passant par 0, soit 30 − (−20) + 1 = 51 valeurs. Un for (c = -20; c < 30; c++) n'en ferait que 50 et oublierait la dernière ligne.

Flowgorithm est le programme utilisé en cours et en TP : on y construit le logigramme avec les mêmes symboles, on l'exécute pas à pas, puis on exporte le programme en C, en Python ou en Java. Le fichier enregistré est un .fprg, du XML lisible : chaque symbole y est un élément.

La règle de correspondance

Flowgorithm compte bornes comprises : start="0" end="n - 1" parcourt les indices 0 à n−1, soit exactement for (i = 0; i < n; i++) en C. Un logigramme qui affiche end="n" décrit un tour de trop, et l'export en C le reproduit.

Ce que Flowgorithm apporte

L'exécution pas à pas montre le chemin dans le logigramme, pas seulement les valeurs : on voit quel losange a été pris, ce qu'aucun débogueur de C ne montre directement. C'est l'outil de la phase « décomposer sur papier », avant l'implémentation.

Le piège

Un logigramme juste ne garantit pas un code juste, et l'inverse est vrai aussi : l'export C d'un <for> mal borné compile sans avertissement. Corrige le logigramme et le code, jamais l'un sans l'autre.

À quel C correspond <do expression="a != 0"> ?
À un do {…} while (a != 0); : le test vient après le corps, donc le corps s'exécute au moins une fois. Dans 1-5.fprg, c'est la boucle du tri à bulles, qui s'arrête quand aucun échange n'a eu lieu.

Erreurs fréquentes : condition inversée, borne, initialisation, diagramme incomplet

Le piège

Une erreur de condition ne se teste pas avec les données de l'énoncé : celui-ci est choisi pour que le cas nominal marche. Ajoute toujours deux essais limites — un caractère non alphabétique, un indice à la borne — avant de conclure qu'un test est correct.

Que vaut cMyfruits[5][0], et que se passe-t-il à la compilation ?
Rien de défini : l'indice 5 est hors du tableau (les indices valides vont de 0 à 4). Le compilateur ne dit rien, l'accès lit la mémoire voisine — comportement indéfini. La borne correcte est i < cNbrOfFruits.

Mémo et checklist

Les symboles et les valeurs à retrouver sans hésiter, puis les contrôles à faire avant de rendre un diagramme ou un programme.

Symboles

  • ovale : début, fin
  • rectangle : traitement, affectation
  • losange : décision, deux sorties
  • parallélogramme : entrée, sortie
  • connecteur : renvoi étiqueté

Pseudocode

  • ← affectation, = comparaison
  • si … alors … sinon … fin si
  • tant que … faire … fin tant que
  • pour i ← 0 à n−1 faire … fin pour
  • un bloc ouvert est fermé, l'indentation porte l'imbrication

Exercice 1.3

  • cNbrOfFruits = 5 (80 / 16 octets)
  • 'o' 0x6F → &= ~0x20 → 'O' 0x4F
  • ~0x20 = −33 (0xFFFFFFDF)
  • cinq tours, cinq lignes de sortie
  • le masque touche firstChar, pas le tableau

Table de trace

  • une ligne par exécution du corps
  • une colonne par variable, plus la condition
  • la sortie recopiée exactement
  • une dernière ligne pour le test qui échoue
  • 5 tours → 5 lignes de corps et 1 ligne de fin
À retenir

Un même algorithme s'écrit quatre fois : pseudocode, diagramme de flux, Nassi-Shneiderman, C. Les trois premières écritures se relisent sans machine ; c'est leur intérêt principal.

Checklist avant de rendre
  • Le pseudocode a ses trois constructions et ses blocs fermés.
  • Chaque losange a deux sorties étiquetées ; chaque boucle revient au test.
  • Le NS a un cadre par boucle et deux colonnes de même hauteur par décision.
  • La table de trace a une ligne par tour et la ligne finale du test.
  • Les bornes sont 0 … n−1 et la sortie est recopiée telle quelle.
  • Le test de plage précède le masque, et un caractère limite a été essayé.
  • Le programme compile avec -std=c11 -Wall -Wextra -Werror -pedantic.
  • Le logigramme et le code disent la même chose, bornes comprises.

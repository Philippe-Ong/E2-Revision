FIFO sur liste chaînée

Implémenter une file FIFO sur liste chaînée : ajout en queue, retrait en tête, tests des cas limites — d'après le corrigé officiel.

exercice 3.1 createFIFO · put · get · Data_t** · pointeur de queue · cas limites théorie : Files FIFO
01
énoncé

Ce que demande l’exercice

Data_t contient sensorNumber (unsigned int), sensorValue (double), time (unsigned long) et pNext (Data_t*).

Trois fonctions sont imposées : createFIFO retourne la tête, put(Data_t**, Data_t) ajoute, get(Data_t**, Data_t*) retire et copie la valeur.

put et get reçoivent l'adresse du pointeur de tête, car ils peuvent le changer ; le booléen signale un échec.

L'énoncé demande aussi showList et un programme qui teste les exceptions, par exemple get sur une liste vide.

Le corrigé officiel (4 pages) donne createFIFO, put, get et showList avec leurs étapes numérotées ; le code ci-dessous en est la transcription, compilée et testée.

02
théorie nécessaire

Les notions à mobiliser

Deux bouts, deux coûts

put ajoute en queue, get retire en tête : premier entré, premier sorti. Une file vide vaut NULL : createFIFO du corrigé fait seulement return NULL;. Avec la seule tête, put parcourt toute la liste (O(n)) et get est O(1).

Data_t** : changer la tête de l'appelant

Un argument est copié : pour changer pList de main, put et get reçoivent &pList, de type Data_t**. *ppList est la tête ; le corrigé la modifie en 5) dans put (liste vide) et en 4) dans get.

put : 1) allouer, 2–3) copier, 4–9) accrocher

1) malloc, false si NULL. Le corrigé montre deux variantes de copie : 2) champ par champ, 3) copie profonde *pElem = newElement ; une seule suffit, mais toutes deux remettent pNext = NULL. 4–5) liste vide : *ppList = pElem. 6–9) sinon pFlow part de la tête, avance tant que pFlow->pNext != NULL, puis pFlow->pNext = pElem.

get : 1) tester, 3–4) détacher, 5) copier, 6) libérer

1) *ppList == NULL → false. 3) pFlow = *ppList, 4) *ppList = pFlow->pNext, 5) copie profonde *pElement = *pFlow, 6) free(pFlow). La copie emporte aussi pNext : il désigne la nouvelle tête, encore valide, mais ne sert pas à parcourir.

03
méthode

Comment procéder

  1. createFIFO : retourner NULL (file vide).
  2. put : allouer et tester malloc, copier l'élément, mettre pNext à NULL.
  3. put : si la file est vide, *ppList = pElem ; sinon parcourir jusqu'au dernier et l'y accrocher.
  4. get : si la file est vide, retourner false ; sinon avancer la tête, copier le nœud sorti, free.
  5. showList : parcourir avec pFlow sans toucher à la tête ; « List is empty... » si NULL.
  6. main : 5 put (sensorValue = 0.1·i²), showList, 5 get, puis showList sur la file vide.
04
application

Application à l’énoncé

exemple.cC11
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>   /* absent du corrigé : nécessaire avant C23 */
#include <time.h>

enum { eNbrOfElements = 5 };

struct Data_s {
    unsigned int  sensorNumber;
    double        sensorValue;
    unsigned long time;
    struct Data_s* pNext;
};
typedef struct Data_s Data_t;

Data_t* createFIFO(void);
bool put(Data_t** ppList, Data_t newElement);
bool get(Data_t** ppList, Data_t* pElement);
void showList(Data_t* pList); /* le corrigé déclare int, définit void */

int main(void)
{
    Data_t* pList = createFIFO();
    for (unsigned int i = 0; i < eNbrOfElements; i++) {
        Data_t element = { i, 0.1 * i * i, time(NULL) + i, NULL };
        if (!put(&pList, element)) {
            printf("No more memory\n");
            exit(-1);
        }
    }
    showList(pList);

    for (unsigned int i = 0; i < eNbrOfElements; i++) {
        Data_t element2 = {0};
        if (!get(&pList, &element2)) {
            printf("Error in getting element...\n");
        } else {
            printf("get: sensor=%d, value=%f, time=%ld\n",
                   element2.sensorNumber, element2.sensorValue, element2.time);
        }
    }
    showList(pList);
    return 0;
}

Data_t* createFIFO(void)
{
    return NULL;
}

bool put(Data_t** ppList, Data_t newElement)
{
    // 1) Allocate memory
    Data_t* pElem = (Data_t*) malloc(sizeof(Data_t));
    if (NULL == pElem) {
        return false;
    }
    // 2) Variante 1 : element by element
    pElem->sensorNumber = newElement.sensorNumber;
    pElem->sensorValue  = newElement.sensorValue;
    pElem->time         = newElement.time;
    pElem->pNext        = NULL;
    // 3) Variante 2 : deep copy of whole element
    *pElem = newElement;
    pElem->pNext = NULL;
    // 4) List empty?
    if (NULL == *ppList) {
        *ppList = pElem;              // 5) Adjust list pointer
        return true;
    } else {
        Data_t* pFlow = *ppList;      // 6) Get first element
        // 7) Iterate to get last element
        while (NULL != pFlow->pNext) {
            pFlow = pFlow->pNext;     // 8) Point to next element
        }
        pFlow->pNext = pElem;         // 9) Last element -> new element
        return true;
    }
}

bool get(Data_t** ppList, Data_t* pElement)
{
    // 1) Check first if list is not empty...
    if (NULL == *ppList) {
        return false;                 // List empty
    } else {
        Data_t* pFlow = *ppList;      // 3) Point to first element
        *ppList = pFlow->pNext;       // 4) Adjust pointer to following element
        *pElement = *pFlow;           // 5) Deep copy of whole element
        free(pFlow);                  // 6) Free retrieved element
        return true;
    }
}

void showList(Data_t* pList)
{
    Data_t* pFlow = pList;            // 1) Check if empty?
    if (NULL == pFlow) {
        printf("List is empty...");
    } else {
        // 2) Parse all elements
        while (NULL != pFlow) {
            printf("sensor=%d, value=%f, time=%ld\n",
                   pFlow->sensorNumber, pFlow->sensorValue, pFlow->time);
            pFlow = pFlow->pNext;
        }
    }
    printf("\n");
}

Le main du corrigé insère cinq éléments sensorNumber 0 à 4 (sensorValue = 0,1·i² : 0, 0,1, 0,4, 0,9, 1,6), les affiche, puis les retire : ils sortent dans l'ordre 0, 1, 2, 3, 4.

Banc de contrôle du corrigé : 38 contrôles, 0 échec (ordre FIFO, get sur file vide, réutilisation après vidage, 10 000 éléments). Pour un put en O(1), on mémoriserait un pointeur de queue pTail.

Résultat. Ordre FIFO conservé : 0 sort le premier ; après cinq get, la tête vaut NULL et showList affiche « List is empty... ».
05
erreurs fréquentes

Les pièges

À vérifier
  • Accrocher en tête au lieu de la queue : la liste devient un LIFO.
  • Oublier free(pFlow) dans get : fuite mémoire à chaque retrait.
  • Ne pas tester malloc : écrire dans le nœud si pElem vaut NULL.
  • Recopier tel quel le corrigé : prototype int showList mais définition void showList (conflicting types), et bool sans avant C23.

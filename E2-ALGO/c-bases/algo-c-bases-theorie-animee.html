01
types

Un type fixe la taille et la façon de lire les bits

Une variable C a un type : il détermine le nombre d'octets réservés, l'intervalle des valeurs et les opérations permises. La norme ne garantit pas la taille de int ; <stdint.h> fournit des types de largeur fixe.

À retenir

Un type est un contrat de lecture : les mêmes quatre octets valent 42 en int, 1,5 en float ou 0x2A en hexadécimal. Changer le type change l'interprétation, pas les bits.

#include <stdio.h>
#include <stdint.h>   /* int8_t … uint64_t, intptr_t */
#include <stddef.h>   /* size_t, ptrdiff_t          */

int main(void)
{
    printf("char     %d octet\n",  (int)sizeof(char));
    printf("int      %d octets\n", (int)sizeof(int));
    printf("long     %d octets\n", (int)sizeof(long));
    printf("pointeur %d octets\n", (int)sizeof(void *));

    uint8_t  octet = 255;          /* 0 … 255            */
    int16_t  petit = -32768;       /* -32 768 … 32 767   */
    uint32_t grand = 4294967295u;  /* 0 … 4 294 967 295  */
    (void)octet; (void)petit; (void)grand;
    return 0;
}
La règle

<stdint.h> fixe la largeur : int8_t, uint16_t, int32_t, uint64_t. size_t est le type non signé d'un résultat de sizeof et d'un indice de tableau ; il fait 8 octets ici. ptrdiff_t est le type signé d'une différence de pointeurs.

char signé ou non signé

Sur cette machine, char est signé : char c = 200; stocke −56, car 200 dépasse 127. Pour manipuler des octets, écris unsigned char ou uint8_t ; pour du texte, char reste le bon type. Le compilateur peut changer ce défaut avec -funsigned-char.

Le piège

sizeof('a') vaut 4, pas 1 : en C, un caractère littéral a le type int. Seul sizeof(char) vaut 1 par définition. Et sizeof rend un size_t : l'afficher avec %d produit un avertissement -Wformat sur une machine 64 bits.

Combien d'octets pour struct { char c; int i; } ?
Huit, pas cinq : le compilateur insère trois octets de bourrage pour aligner i sur 4 octets. La taille d'une structure ne s'additionne pas, elle se mesure avec sizeof.
02
variables

Quatre classes de stockage, trois durées de vie

Déclarer donne un type et un nom ; définir réserve la mémoire ; initialiser donne une première valeur ; affecter écrit ensuite. La classe de stockage décide où la variable existe, qui la voit et combien de temps elle vit.

stockage.c
#include <stdio.h>

int global = 10;            /* visible dans tout le programme */
static int fichier = 20;    /* visible dans ce fichier seulement */

int getCount(void)
{
    static int count = 0;   /* initialisée une seule fois, avant main */
    count++;
    return count;
}

int main(void)
{
    int local = 5;          /* automatique : détruite à la fin du bloc */
    printf("%d\n", getCount());   /* 1 */
    printf("%d\n", getCount());   /* 2 */
    printf("%d\n", getCount());   /* 3 */
    return local + global + fichier;   /* utilise la variable static */
}
La règle

Une variable static locale est créée une seule fois et garde sa valeur d'un appel à l'autre. Une variable globale ou static globale est initialisée à zéro avant main. Une variable locale automatique non initialisée contient une valeur indéterminée : la lire est une erreur de logique, pas une valeur par défaut.

masquage.c
#include <stdio.h>

int i = 1;                  /* globale */

int getVal(void)
{
    static int i = 2;       /* cache la globale */
    i++;
    for (int i = 0; i < 10; ) {
        i++;                /* troisième i, local au for */
    }
    return i;               /* rend le static : 3 */
}

int main(void)
{
    int i = 10;             /* cache la globale dans main */
    i = getVal();
    printf("i=%d!\n", i);   /* i=3! */
    return 0;
}

Le nom le plus proche gagne : la globale i vaut 1, le static de getVal passe de 2 à 3, et la boucle for utilise sa propre variable, détruite à la fin du bloc. main affiche donc i=3!.

const et volatile

const promet une lecture seule après initialisation : float const PI = 3.14159265358979f;. volatile prévient le compilateur que la valeur peut changer hors du programme (registre, interruption) : il ne doit pas la mettre en cache.

Le piège

static int count = 0; dans une fonction ne remet pas count à zéro à chaque appel : l'initialisation n'a lieu qu'une fois. Après trois appels, getCount() rend 3. Pour repartir de zéro, il faut une variable automatique.

Une variable globale non initialisée vaut-elle « n'importe quoi » ?
Non : elle est initialisée à zéro avant main, comme une static. Ce sont les variables automatiques (locales sans static) qui ne sont pas initialisées.

Le C évalue selon une table de priorité et d'associativité. Trois règles expliquent presque tout : * / % passent avant + -, les comparaisons passent avant && et ||, et l'affectation vient à la fin.

Division et modulo

Si les deux opérandes sont entiers, / tronque vers zéro et % donne le reste de cette division. % n'accepte pas de flottants. Le signe du reste est celui du dividende.

Incrément, décrément et opérateurs bit à bit

++x incrémente puis rend la nouvelle valeur ; x++ rend l'ancienne puis incrémente. La différence ne se voit que dans une expression plus large.

Séquence du cours, valeurs vérifiées

Les opérateurs bit à bit travaillent sur les bits d'un entier : 12 & 10 = 8, 12 | 10 = 14, 12 ^ 10 = 6, ~12 = −13. En ASCII, 'a' = 0x61 et 'A' = 0x41 : 'a' & ~0x20 donne 'A', 'A' | 0x20 donne 'a'.

    == et != passent avant &. x & m == 0 se lit donc x & (m == 0) : écris (x & m) == 0. Même famille : a + b * 3 ne vaut pas (a + b) * 3, et !x == 0 se lit (!x) == 0.

    04
    évaluation

    Court-circuit, effets de bord et conversions

    Deux propriétés décident du résultat : l'ordre d'évaluation des opérandes n'est pas garanti, et && / || n'évaluent le second opérande que si le premier ne suffit pas. Une expression qui modifie deux fois la même variable n'a pas de résultat défini.

    court-circuit.c
    /* le second opérande n'est évalué que si p n'est pas NULL */
if (p != NULL && *p > 0) {
    printf("%d\n", *p);
}

/* pas d'accès hors bornes : la comparaison borne l'indice */
for (size_t i = 0; i < n && a[i] > 0; i++) {
    somme += a[i];
}

/* || s'arrête au premier vrai : le deuxième appel n'a pas lieu */
if (ok || verifier()) {
    /* ... */
}
    La règle

    && et || garantissent l'ordre gauche → droite et le court-circuit. Les autres opérateurs ne garantissent pas l'ordre d'évaluation de leurs opérandes : f() + g() ne dit pas si f passe avant g. Une expression ne doit pas dépendre de cet ordre.

    ub.c
    int i = 0;
i = i++ + 1;          /* indéfini : i modifié deux fois sans point de séquence */

int x = 2147483647;   /* INT_MAX */
x = x + 1;            /* indéfini : dépassement d'un int signé              */

unsigned u = 4294967295u;   /* UINT_MAX */
u = u + 1;                  /* défini : 0, modulo 2^32                 */
    Dépassement signé

    Un int signé qui dépasse INT_MAX provoque un comportement indéfini. gcc peut replier la valeur, l'optimiser ou faire autre chose : aucune réponse n'est garantie. Un unsigned déborde de façon définie, modulo 2N : UINT_MAX + 1 vaut 0.

    Deux modifications de la même variable

    La ligne 6 de l'exercice 1.1 e), k = k++ + ++j;, n'a pas un résultat : c'est un comportement indéfini. La sortie de l'énoncé (k = 12, j = 7) n'est qu'une possibilité de gcc. gcc -Wall avertit « operation on 'k' may be undefined ».

    Conversions : ce que devient le type

    Dans une expression, char et short sont promus en int ; dès qu'un double participe, le calcul se fait en double. Une affectation convertit ensuite vers le type de la variable, avec perte possible.

    Le piège du mélange signé / non signé

    if (-1 < 1u) est faux, parce que -1 est converti en unsigned avant la comparaison. -Wextra signale « comparison of integer expressions of different signedness ». Compare des types de même signe, ou caste explicitement.

    Pourquoi i = i++ + 1; n'a-t-il pas de valeur ?
    Parce que i est modifié deux fois entre deux points de séquence, sans ordre défini. La norme C11 qualifie ce cas de comportement indéfini : le compilateur peut produire n'importe quoi, y compris ce qui semble marcher.
    05
    contrôle

    Conditions et boucles : choisir un chemin, répéter un bloc

    if choisit, switch sélectionne parmi des constantes entières, et trois boucles répètent avec un test avant (while, for) ou après (do…while). break sort, continue passe au tour suivant.

    controle.c
    int note = 5;
if (note >= 5) {
    printf("réussi\n");
} else {
    printf("insuffisant\n");
}

switch (note) {
    case 6:  printf("très bien\n"); break;
    case 5:  printf("bien\n");      break;
    default: printf("insuffisant\n");
}

for (int i = 0; i < 4; i++) {          /* test avant, 4 tours */
    printf("%d ", i);
}

int i = 0;
while (i < 4) {                        /* test avant, 0 tour possible */
    printf("%d ", i);
    i++;
}

int j = 0;
do {                                   /* test après, au moins 1 tour */
    printf("%d ", j);
    j++;
} while (j < 4);
    Les trois boucles
    boucletesttours minimumusage
    for (init; cond; pas)avant le corps0nombre de tours connu ou compteur
    while (cond)avant le corps0répéter tant qu'une condition tient
    do { } while (cond);après le corps1au moins une exécution, puis test
    La règle du for

    init une seule fois ; cond avant chaque tour ; pas après chaque corps, y compris après un continue. Depuis C99, la variable peut être déclarée dans init : for (int i = 0; …).

    La règle du switch

    Chaque case doit être une constante entière. Sans break, l'exécution continue dans le case suivant : c'est le fall through, parfois voulu, toujours à commenter. default traite les valeurs non prévues.

      Le point-virgule de trop

      if (x > 0); termine l'instruction : le bloc suivant s'exécute toujours. Même faute avec for (i = 0; i < n; i++); ou while (i < n);. gcc signale « suggest braces around empty body in an 'if' statement » avec -Wextra.

      Combien de tours pour for (int i = 0; i < 0; i++), et pour un do…while de même condition ?
      Zéro tour pour le for (test avant) ; un tour pour le do…while (test après), même si la condition est fausse dès le départ.
      06
      fonctions

      Le C passe tout par valeur, y compris les adresses

      Une fonction a un prototype (type de retour, nom, paramètres), une définition et des appels. Les arguments sont copiés : pour modifier une variable de l'appelant, il faut passer son adresse.

      fonctions.c
      #include <stdio.h>

double celsiusToFahrenheit(double c);   /* prototype */

double celsiusToFahrenheit(double c)    /* définition */
{
    return c * 1.8 + 32.0;
}

void swap(int *pX, int *pY)             /* passage par adresse */
{
    int tmp = *pX;
    *pX = *pY;
    *pY = tmp;
}

int main(void)
{
    double f = celsiusToFahrenheit(10.0);   /* 50.0 */
    int x = 13, y = 15;
    swap(&x, &y);                          /* x = 15, y = 13 */
    printf("%.1f %d %d\n", f, x, y);
    return 0;
}
      La règle

      void f(void) déclare une fonction sans paramètre. void f() laisse la liste non spécifiée : en C, ce n'est pas la même chose. Une fonction static n'est visible que dans son fichier .c.

      Trois placements pour le prototype : avant main ; définition avant main (le prototype est alors inutile) ; prototype dans un .h inclus et définition dans un .c. Le troisième est la forme des projets à plusieurs fichiers.

      swap.c
      void swap_bad(int a, int b) { int t = a; a = b; b = t; }        /* copies  */
void swap_ok (int *a, int *b) { int t = *a; *a = *b; *b = t; } /* adresses */

int main(void)
{
    int x = 1, y = 2;
    swap_bad(x, y);      /* x = 1, y = 2 : rien ne change */
    swap_ok(&x, &y);     /* x = 2, y = 1 : le swap a lieu */
}
      Laboratoire · pile d'appels
      une copie de l'argument, une valeur de retour
      6 états
      Tableau en paramètre

      void f(int a[10]) et void f(int *a) déclarent la même chose : un pointeur. La taille 10 est ignorée, sizeof(a) vaut 8 dans la fonction. Passe toujours size_t n avec le tableau.

      Renvoyer une adresse locale

      int *bad(void) { int local = 42; return &local; } renvoie une adresse qui ne survit pas au retour : la pile sera réutilisée. Trois retours sûrs seulement : un objet static, un bloc malloc, ou un objet de l'appelant passé en argument.

      Pourquoi swap_bad(x, y) ne change-t-il rien ?
      La fonction reçoit des copies de x et y, échange ses copies, puis les détruit au retour. Il faut passer les adresses : swap_ok(&x, &y), et écrire *a et *b dans le corps.
      07
      tableaux

      Tableau : des cases contiguës, indexées de 0 à n−1

      Un tableau réserve n éléments du même type, côte à côte. Le C ne vérifie pas les indices. Une chaîne est un tableau de char terminé par '\0', ce qui ajoute toujours un octet à la longueur visible.

      tableaux.c
      #include <stdio.h>
#include <string.h>

int a[4] = {10, 20, 30, 40};
size_t n = sizeof a / sizeof a[0];   /* 16 / 4 = 4 */

char s[] = "algo";   /* 5 octets : 'a', 'l', 'g', 'o', '\0' */
char *t  = "algo";   /* pointeur vers un littéral en lecture seule */

printf("%d\n", a[2]);          /* 30 */
printf("%d\n", a[n - 1]);      /* 40 : dernier indice valide */
printf("%zu %zu\n", sizeof s, strlen(s));   /* 5 puis 4 */
printf("%zu %zu\n", sizeof a, sizeof t);    /* 16 puis 8 */
      Cinq tailles à distinguer
      expressionvaleursens
      sizeof a16le tableau entier (4 × 4 octets)
      sizeof a[0]4un élément
      sizeof s5le tableau de char, terminateur compris
      strlen(s)4les caractères avant '\0'
      sizeof t8le pointeur, pas la chaîne
      La règle

      Les indices valides vont de 0 à n−1. Le nombre d'éléments se calcule avec sizeof a / sizeof a[0], et seulement là où le tableau est déclaré : dans une fonction, a est devenu un pointeur.

      Tableaux à deux dimensions

      int m[4][2] est un tableau de 4 lignes de 2 int, rangé ligne par ligne. m[i][j] se trouve à l'offset i * 2 + j éléments. La ligne i commence à m + i, soit i * 8 octets plus loin.

      Applications

      La fiche Pointeurs en C détaille a[i] == *(a + i), l'arithmétique des pointeurs et la différence entre char s[] et char *t (sections 06 et 07).

      Le tableau trop court

      char s[4] = "algo"; est accepté par le compilateur : les quatre caractères remplissent le tableau, mais le '\0' n'a pas de place. strlen(s) lit alors au-delà du tableau. Prévois toujours strlen + 1 octets.

      Que vaut sizeof a / sizeof a[0] dans une fonction qui reçoit int a[10] ?
      2 sur cette machine : a est un pointeur de 8 octets, a[0] un int de 4. La taille 10 de la déclaration est ignorée ; il faut passer n en paramètre.
      08
      structures

      Structure : des champs nommés ; énumération : des constantes nommées

      Une structure groupe des données de types différents ; une énumération donne des noms à des constantes entières. L'accès se fait par . sur une structure et -> sur un pointeur de structure.

      structures.c
      typedef struct {
    int x;
    int y;
} Point_t;                       /* 8 octets : 4 + 4 */

typedef enum {
    eBLEU,                        /* 0  */
    eJAUNE = 10,                  /* 10 */
    eVERT,                        /* 11 */
    eROUGE = 30                   /* 30 */
} Couleur_t;

Point_t pt = {12, 34};
Point_t *p = &pt;

printf("%d\n", pt.x);    /* 12 : la structure elle-même   */
p->x = 10;               /* (*p).x = 10 : par le pointeur */
printf("%d\n", pt.x);    /* 10 : même objet, autre accès  */
      La règle

      Une énumération attribue 0 au premier identifiant, puis +1 à chaque suivant, sauf valeur explicite. Ses constantes sont de type int : enum { eNB = 10 }; est une façon propre de nommer une taille de tableau. enum ne vérifie pas les valeurs à l'exécution.

      Union

      Une union superpose ses membres au même endroit : sa taille est celle du plus grand. Le cours l'utilise pour voir un registre en 16 bits ou en deux octets, et pour convertir des types.

      Applications

      La fiche Structures et types composés détaille les tableaux de structures, les structures imbriquées et le carnet d'adresses. La fiche Pointeurs en C reprend p->x, (*p).x et le bourrage.

      Le piège

      p.x ne compile pas si p est un pointeur, et pt->x ne compile pas si pt est une structure. Et sizeof(struct { char c; int i; }) vaut 8, pas 5 : le bourrage aligne i. Ne calcule jamais une taille de structure en additionnant ses membres.

      Que valent eVERT et eROUGE dans l'énumération ci-dessus ?
      11 et 30. eJAUNE = 10 fixe le suivant à 11 ; eROUGE = 30 impose 30 explicitement.

      entrées/sorties

      printf formate, scanf lit à une adresse

      printf convertit chaque argument selon le format ; scanf reçoit l'adresse de la variable à remplir. Un format qui ne correspond pas au type est une erreur, signalée par -Wformat quand le format est un littéral.

      Formats usuels

      La règle de scanf

      Chaque conversion attend une adresse : scanf("%d", &x). La valeur de retour est le nombre de conversions réussies : teste if (scanf("%d", &x) != 1). Pour une chaîne, borne la lecture : scanf("%7s", s) pour un char s[8].

      entrees-sorties.c
      #include <stdio.h>

int x = 0;
char c = 'A';
char s[6] = "algo";

printf("Entier ? ");
if (scanf("%d", &x) != 1) {   /* l'adresse de x, pas sa valeur */
    return 1;
}
printf("x = %d\n", x);         /* 42 si la saisie vaut 42     */
printf("%d %c %s\n", x, c, s); /* 42 A algo                   */
printf("[%5.2f] [%02d]\n", 3.14159, 7);   /* [ 3.14] [07]    */

        Le piège

        scanf("%d", x) oublie & : gcc le signale avec -Wall, mais sans avertissement le programme écrit à l'adresse 0. Autres confusions : %f attend un double dans printf mais un double * dans scanf ; %d sur un size_t ou un pointeur est une erreur de format.

        %zu sous MinGW

        Le contrôle de format de gcc utilise ici ms_printf, qui ne connaît pas %z : printf("%zu", sizeof(int)) produit « unknown conversion type character 'z' ». Compile avec -D__USE_MINGW_ANSI_STDIO=1, ou caste : printf("%llu", (unsigned long long)sizeof(int)).

        Applications

        La suite du programme lit des fichiers avec fgets : voir la fiche Entrées/sorties et fichiers et l'énoncé de l'exercice 2.6 (affichage du contenu d'un fichier, option -l).

        Que rend scanf("%d", &x) si la saisie est abc ?
        0 : aucune conversion n'a réussi, et x n'est pas modifiée. La valeur de retour permet de distinguer une saisie valide d'une saisie refusée.

        La méthode

        Compiler souvent, corriger la première erreur, recompiler. Une erreur de syntaxe en cache souvent plusieurs. Une erreur d'édition de liens (« undefined reference ») n'est pas une faute de frappe : c'est un symbole défini nulle part, ou déclaré static dans un autre fichier.

        Déboguer dans VS Code ou gdb

        Dans VS Code : launch.json avec "stopAtEntry": true pour s'arrêter dans main, "externalConsole": true pour voir les printf ; tasks.json avec -g -Wall -std=c11. En ligne de commande : gdb main.exe, puis break main, run, next, print x, backtrace.

        Les sanitizers ne sont pas toujours là

        Sur cette installation MinGW (gcc 13.2), -fsanitize=address et -fsanitize=undefined échouent à l'édition de liens (cannot find -lasan, -lubsan). Utilise -g et gdb, ou un autre toolchain. Sur Linux, ces options détectent les débordements et les usages après free.

        Un programme qui compile sans avertissement est-il correct ?
        Non. Un dépassement de tableau, une division par zéro ou un accès après free compilent sans aucun message. Les avertissements couvrent les erreurs statiques, pas le comportement à l'exécution.

        Mémo et checklist

        Les valeurs et les formats à retrouver sans hésiter, puis les contrôles à faire avant de rendre un programme.

        Tailles (MinGW 64 bits)

        typeoctets
        char1
        short2
        int4
        long4
        long long8
        float4
        double8
        void *8

        Formats

        • %d int · %u unsigned
        • %lld long long · %zu size_t
        • %f double en printf · %lf en scanf
        • %c char · %s chaîne · %p void *

        Priorités

        • * / % avant + -
        • comparaisons avant && et ||
        • == avant & : parenthéser (x & m) == 0
        • affectation en dernier, associée à droite

        Huit réflexes

        • Initialiser toute variable locale.
        • Un int ne dépasse pas INT_MAX.
        • Division entière : caster avant de diviser.
        • scanf : toujours &, sauf pour une chaîne.
        • Tableau : indices 0 … n-1, n = sizeof a / sizeof a[0].
        • Chaîne : strlen + 1 octets.
        • Fonction : passer l'adresse pour modifier l'appelant.
        • Compiler avec -Wall -Wextra -Werror -pedantic.
        À retenir

        Un programme C se relit avec trois questions : quel type a chaque valeur, quelle valeur produit chaque expression, quelle durée de vie a chaque objet. Les erreurs du chapitre 1 sont presque toujours une de ces trois réponses qui manque.

        Checklist avant de rendre
        • Le programme compile avec -std=c11 -Wall -Wextra -Werror -pedantic.
        • Chaque variable locale est initialisée avant sa première lecture.
        • Chaque boucle modifie la variable testée ; chaque switch a ses break.
        • Chaque scanf reçoit une adresse et sa valeur de retour est testée.
        • Chaque tableau est borné par n et chaque chaîne a son '\0'.
        • Le format de chaque printf correspond au type de l'argument.
        • Les cas limites sont essayés : 0, valeur négative, borne haute, tableau vide.
        • Le code est exécuté sous gdb ou dans VS Code si un résultat surprend.

Exercices 3.1
01
l'idée

Une liste est une chaîne de nœuds

Un nœud contient deux choses : une valeur et l'adresse du nœud suivant. Il n'y a donc ni indice, ni longueur, ni bloc contigu — seulement une chaîne de pointeurs et une seule façon d'entrer : la tête.

À retenir

Un tableau est une rangée de casiers numérotés, collés : on accède directement au casier 7. Une liste est une chaîne : chaque nœud contient une valeur et l'adresse du suivant, donc atteindre le cinquième impose de lire les quatre premiers. Si l'on perd la tête, le reste devient inaccessible même s'il existe encore.

Trois mots de vocabulaire, et tout est dit

  • Nœud (node) : une structure allouée par malloc, qui contient la donnée et un pointeur pNext vers le nœud suivant.
  • Tête (head) : le pointeur vers le premier nœud. C'est la seule variable qui rend la liste accessible — la cours l'appelle pBegin, l'exercice 3.1 pList.
  • NULL : la valeur de pNext du dernier nœud. C'est le terminateur de la liste, exactement comme '\0' termine une chaîne.
La règle fondatrice

La liste n'existe que par sa tête. pBegin == NULL signifie « aucun nœud » : c'est la liste vide, et c'est l'état initial de createFIFO(). Toute opération commence donc par regarder cette tête : est-elle nulle ? faut-il la modifier ?

La différence qui fait mal

Un tableau connaît sa longueur et son dernier élément sans rien parcourir. Une liste n'en sait rien : le « dernier nœud » n'est pas une adresse connue, c'est le nœud dont le pNext vaut NULL. Trouver la fin, c'est donc déjà parcourir. C'est ce qui rend l'insertion en queue O(n) et non O(1).

02
structure & mémoire

Un nœud = une structure qui se contient elle-même (par pointeur)

La définition a l'air de se mordre la queue : struct Node_s contient un pointeur vers struct Node_s. C'est légal — et c'est même la seule façon d'écrire une liste en C — parce qu'un pointeur a une taille connue : 8 octets, quel que soit ce qu'il vise.

node.h
#include <stdlib.h>
#include <stdbool.h>

/* Le nœud des laboratoires : 16 octets sur une machine 64 bits. */
typedef struct Node_s
{
    int             value;   /*  4 octets            */
                             /*  4 octets de bourrage */
    struct Node_s * pNext;   /*  8 octets : l'adresse du suivant, ou NULL */
} Node_t;

/* La structure du cours et de l'exercice 3.1 : 32 octets. */
typedef struct Data_s
{
    int             sensorNumber;
    double          sensorValue;
    long            time;
    struct Data_s * pNext;
} Data_t;

Le typedef struct Node_s Node_t; n'est qu'un raccourci d'écriture : il évite de répéter struct. À l'intérieur de la structure, le nom complet struct Node_s * reste obligatoire, car le typedef n'existe pas encore à cet endroit du fichier.

Allouer, remplir, libérer

allouer.c
#include <stdlib.h>

Node_t *creerNode(int valeur)
{
    Node_t *pNew = malloc(sizeof *pNew);   /* 16 octets, contenu indéterminé */
    if (pNew == NULL) return NULL;         /* plus de mémoire : on n'écrit rien */

    pNew->value = valeur;
    pNew->pNext = NULL;                    /* le nouveau nœud termine la liste */
    return pNew;
}

void libererNode(Node_t *p)
{
    free(p);        /* rend le bloc au tas ; p devient suspendu */
    p = NULL;       /* ne sert à rien ici : p est une copie locale */
}
Le piège du sizeof

malloc(sizeof pNew) réserve 8 octets — la taille du pointeur — puis on écrit 16 octets dedans : c'est un débordement de tas, et souvent un plantage ailleurs. Écris toujours malloc(sizeof *pNew), qui vaut 16. La règle vaut pour tous les malloc du cours.

Les adresses de cette page

Les variables locales vivent sur la pile : pBegin à 0x2000, pFlow à 0x2008, pNew à 0x2010. Les nœuds vivent dans le tas : 0x3000, 0x3010, 0x3020, 0x3030. Ces valeurs sont symboliques : elles servent à suivre les flèches, pas à décrire ta machine.

La variante du cours : le nœud sentinelle

Dans les diapositives, main alloue d'abord un nœud « factice » (pBegin = malloc(...); pBegin->pNext = NULL;) avant d'appeler addToList. Avantage : pBegin n'est jamais NULL, donc pFlow->pNext dans la boucle ne déréférence jamais NULL, et la liste vide a quand même une tête. Inconvénient : un nœud de plus, et les fonctions doivent ignorer cette sentinelle. L'exercice 3.1 fait l'inverse — pas de sentinelle, liste vide ⇔ pList == NULL — et doit donc tester la liste vide avant tout parcours. Les deux sont corrects ; il faut savoir dans quel monde on écrit.

03
parcours

Parcourir : un pointeur de travail, jamais la tête

Tout parcours de liste suit le même patron : un pointeur de travail pFlow démarre sur la tête, on traite le nœud, puis pFlow = pFlow->pNext jusqu'à NULL. La tête, elle, ne bouge pas — c'est la règle qui sauve la liste.

parcours.c
/* compter — la forme sûre, valable avec ou sans nœud sentinelle */
int count(const Node_t *pHead)
{
    int n = 0;
    for (const Node_t *pFlow = pHead; pFlow != NULL; pFlow = pFlow->pNext)
    {
        n++;
    }
    return n;
}

/* chercher la première valeur égale à cible, ou NULL */
Node_t *find(Node_t *pHead, int cible)
{
    Node_t *pFlow = pHead;
    while (pFlow != NULL)
    {
        if (pFlow->value == cible) return pFlow;   /* on renvoie le nœud */
        pFlow = pFlow->pNext;
    }
    return NULL;                                    /* pas trouvé */
}

/* afficher — on garde pFlow pour ne pas abîmer l'appelant */
void printList(const Node_t *pFlow)
{
    while (pFlow != NULL)
    {
        printf("value = %d\n", pFlow->value);
        pFlow = pFlow->pNext;
    }
}
La règle du parcours

La tête est un paramètre d'entrée, pFlow est un outil jetable. On ne réaffecte jamais pBegin, jamais le paramètre pHead — seulement pFlow. Même en const Node_t * : la fonction peut lire toute la liste sans risque de la casser.

Le compteur du cours, et son piège

Les diapositives écrivent while (NULL != pFlow->pNext) { number++; pFlow = pFlow->pNext; } en partant de pBegin. Avec le nœud sentinelle du cours, cela donne le bon nombre d'éléments utiles. Sans sentinelle — le choix de l'exercice 3.1 — la même boucle s'arrête un nœud trop tôt : pour A → B → C elle renvoie 2 au lieu de 3. La forme sûre compte avec while (pFlow != NULL), comme ci-dessus.

Le parcours qui transforme : inverser sans rien allouer

Inverser une liste ne coûte aucun malloc : on retourne les flèches une par une. Trois pointeurs suffisent — pPrev (le passé), pFlow (le présent), pNext (le futur) — et l'ordre des quatre affectations est toute la difficulté.

L'erreur d'ordre de l'inversion

Si tu écris pFlow->pNext = pPrev; avant pNext = pFlow->pNext;, la suite de la liste est écrasée : pNext reçoit l'ancienne valeur de pPrev, et B, C sont perdus. C'est le même réflexe que pour l'insertion : sauver d'abord, écraser ensuite.

04
insertion en tête

Insérer en tête : trois affectations, O(1)

C'est l'opération reine de la liste chaînée, celle qui justifie tout le chapitre : ajouter un élément devant coûte le même temps que la liste ait 3 nœuds ou 3 millions. Aucune boucle, aucun décalage.

Laboratoire · insérer C devant A
tête → A → B, puis C en tête
7 étapes
insert_head.c
/* O(1) : aucune boucle, deux affectations de liens.
   ppHead permet de modifier la tête de l'appelant.            */
bool insertHead(Node_t **ppHead, int value)
{
    if (ppHead == NULL) return false;              /* pointeur invalide */

    Node_t *pNew = malloc(sizeof *pNew);
    if (pNew == NULL) return false;                /* plus de mémoire : liste intacte */

    pNew->value = value;
    pNew->pNext = *ppHead;   /* 1. le nouveau regarde l'ancienne tête  */
    *ppHead     = pNew;      /* 2. la tête devient le nouveau          */
    return true;
}

/* appel : insertHead(&pBegin, 30);  — surtout pas insertHead(pBegin, 30); */
La règle d'ordre

Toujours le nouveau vers l'ancien d'abord, puis la tête vers le nouveau. Écrit sous forme de phrase : « le nouveau nœud apprend le chemin, puis on lui donne la clé de la porte ». L'inverse fait pointer le nouveau sur lui-même.

Deux pièges, pas un

Ordre : voir ci-dessus. Signature : void insertHead(Node_t *pHead, int v) ne peut pas changer la tête de l'appelant — pHead est une copie du pointeur. Il faut Node_t **ppHead, ou renvoyer la nouvelle tête et écrire pBegin = insertHead(pBegin, 30);. C'est exactement le Data_t** ppList de l'exercice 3.1.

Combien de nœuds faut-il déplacer pour insérer en tête d'un tableau de 1 000 000 d'entiers ?
Les 1 000 000 : il faut décaler chaque case d'un rang vers la droite, soit O(n). La liste, elle, ne déplace rien : elle écrit deux pointeurs. C'est cet écart qui rend les listes irremplaçables dans les files d'attente et les historiques.
05
insertion en queue

Insérer en queue : O(n)… ou O(1) avec un pointeur de queue

Ajouter derrière, c'est ajouter après le dernier. Or « le dernier » n'est pas connu : c'est celui dont le pNext vaut NULL. Avec la seule tête, il faut donc traverser — sauf si l'on garde aussi l'adresse de la queue.

insert_tail.c
/* Variante 1 — la seule tête : O(n), il faut traverser. */
bool pushBack(Data_t **ppList, Data_t newElement)
{
    Data_t *pNew = malloc(sizeof *pNew);
    if (pNew == NULL) return false;

    *pNew = newElement;          /* recopie des champs utiles */
    pNew->pNext = NULL;          /* le nouveau termine toujours la liste */

    if (*ppList == NULL)         /* liste vide : cas à part, sinon NULL->pNext */
    {
        *ppList = pNew;
    }
    else
    {
        Data_t *pFlow = *ppList;
        while (pFlow->pNext != NULL) pFlow = pFlow->pNext;   /* le dernier */
        pFlow->pNext = pNew;
    }
    return true;
}

/* Variante 2 — tête + queue : O(1), aucune boucle. */
typedef struct { Node_t *pHead; Node_t *pTail; } List_t;

bool pushBackFast(List_t *pList, int value)
{
    Node_t *pNew = malloc(sizeof *pNew);
    if (pNew == NULL) return false;
    pNew->value = value;
    pNew->pNext = NULL;

    if (pList->pTail == NULL) { pList->pHead = pNew; pList->pTail = pNew; }
    else
    {
        pList->pTail->pNext = pNew;   /* 1. l'ancien dernier pointe sur pNew */
        pList->pTail = pNew;          /* 2. pNew devient le dernier          */
    }
    return true;
}

Pourquoi la queue ne fait pas tout

pTail accélère l'ajout, mais pas le retrait en queue : pour supprimer le dernier, il faut mettre le pNext de l'avant-dernier à NULL, donc retrouver l'avant-dernier — un parcours en O(n). Sauf en liste doublement chaînée, où pTail->pPrev donne l'avant-dernier en O(1).

L'ordre et la queue

pTail = pNew; écrit avant pTail->pNext = pNew; fait perdre l'ancien dernier : la chaîne n'est plus reliée, et le nouveau pointe sur lui-même. Même réflexe qu'en tête : relier d'abord, déplacer l'indicateur ensuite. Et n'oublie pas : après un retrait du dernier, pTail doit être recalculé (ou remis à NULL si la liste devient vide).

06
insertion au milieu

Insérer au milieu : trouver, puis accrocher

Insérer après un nœud p est trivial — quatre lignes. Ce qui coûte, c'est de trouver p. D'où la règle constante du chapitre : la liste chaînée ne rend pas l'insertion rapide, elle rend l'insertion rapide une fois qu'on est sur place.

insert_after.c
/* Insérer APRÈS le nœud p, qui doit exister.
   Si p est le dernier nœud, p->pNext vaut NULL : ça marche aussi. */
bool insertAfter(Node_t *p, int value)
{
    if (p == NULL) return false;              /* pas de point d'ancrage */

    Node_t *pNew = malloc(sizeof *pNew);
    if (pNew == NULL) return false;

    pNew->value = value;
    pNew->pNext = p->pNext;   /* 1. le nouveau récupère la suite */
    p->pNext    = pNew;       /* 2. p pointe maintenant sur le nouveau */

    return true;
}

/* insertion à la position index (0 = tête), avec accès à la tête */
bool insertAt(Node_t **ppHead, int index, int value)
{
    if (index == 0) return insertHead(ppHead, value);   /* cas de la tête */

    Node_t *pFlow = *ppHead;
    for (int i = 0; i < index - 1 && pFlow != NULL; i++)
    {
        pFlow = pFlow->pNext;              /* on cherche le nœud AVANT */
    }
    if (pFlow == NULL) return false;       /* index hors de la liste */
    return insertAfter(pFlow, value);
}
Les deux affectations, dans l'ordre

pNew->pNext = p->pNext; puis p->pNext = pNew;. Comme pour la tête : le nouveau apprend le chemin avant qu'on coupe l'ancien. Si tu écris p->pNext = pNew; d'abord, la suite de la liste est perdue — tu ne peux plus la retrouver.

Insérer avant un nœud, sans pointeur arrière

Impossible directement : rien ne remonte de p vers son prédécesseur. La parade classique est de copier la valeur du suivant dans le nœud courant, puis d'insérer la nouvelle valeur après — mais alors les adresses de nœuds changent de sens, ce qui interdit cette astuce si d'autres pointeurs visent ces nœuds. La vraie réponse est la liste doublement chaînée, section 8.

Peut-on écrire if (p == NULL) return insertHead(...) à l'intérieur de insertAfter ?
Non, pas avec un simple Node_t *p : p est une copie, la modifier ne change pas la tête de l'appelant. Il faudrait passer Node_t **ppHead. C'est encore le même point : qui possède la tête doit pouvoir la réécrire.
07
suppression

Supprimer : recâbler d'abord, free ensuite

Supprimer un nœud, c'est faire sauter un wagon : le précédent doit être accroché au suivant avant qu'on enlève le wagon. Et si c'est la tête qui saute, c'est pBegin lui-même qu'il faut déplacer.

delete.c
/* Supprimer l'élément d'indice index. O(n) : il faut atteindre le prédécesseur. */
bool deleteAt(Node_t **ppHead, int index)
{
    if (ppHead == NULL || *ppHead == NULL) return false;   /* liste vide      */

    if (index == 0)                                        /* cas de la tête  */
    {
        Node_t *pOld = *ppHead;
        *ppHead = pOld->pNext;
        free(pOld);
        return true;
    }

    Node_t *pFlow = *ppHead;                               /* le prédécesseur */
    for (int i = 0; i < index - 1; i++)
    {
        if (pFlow->pNext == NULL) return false;            /* index trop grand */
        pFlow = pFlow->pNext;
    }

    Node_t *pOld = pFlow->pNext;                           /* le condamné     */
    if (pOld == NULL) return false;                        /* rien à supprimer */
    pFlow->pNext = pOld->pNext;                            /* 1. recâbler      */
    free(pOld);                                            /* 2. libérer       */
    return true;
}

/* Tout libérer avant de quitter : un free par malloc. */
void deleteList(Node_t **ppHead)
{
    Node_t *pFlow = *ppHead;
    while (pFlow != NULL)
    {
        Node_t *pNext = pFlow->pNext;   /* sauver AVANT de libérer */
        free(pFlow);
        pFlow = pNext;
    }
    *ppHead = NULL;
}
La règle de la suppression

Trois temps, toujours dans cet ordre : mémoriser (pOld), recâbler (pFlow->pNext = pOld->pNext), libérer (free(pOld)). Et un quatrième réflexe : mettre à jour pTail si le nœud supprimé était le dernier.

Le parcours pendant la suppression

free(pFlow); pFlow = pFlow->pNext; est un comportement indéfini : on lit un champ après libération. Il faut sauver d'abord : pNext = pFlow->pNext; free(pFlow); pFlow = pNext;. C'est exactement le patron de deleteList ci-dessus.

08
doublement chaînée

Doublement chaînée : un lien de plus, deux directions

Chaque nœud reçoit un second pointeur, pPrev, vers le nœud précédent. Prix : 8 octets de plus par nœud. Gain : on remonte, et surtout on supprime un nœud connu en O(1) — sans chercher son prédécesseur.

dnode.h
typedef struct DNode_s
{
    struct DNode_s *pPrev;   /*  8 octets : le précédent, ou NULL pour la tête  */
    int             value;   /*  4 octets + 4 de bourrage                       */
    struct DNode_s *pNext;   /*  8 octets : le suivant, ou NULL pour la queue   */
} DNode_t;                   /* sizeof = 24 octets                              */

/* La liste garde les deux extrémités : c'est là que tout se joue. */
typedef struct { DNode_t *pHead; DNode_t *pTail; } DList_t;

dlists.c
/* Insérer pNew APRÈS p — 4 liens, aucun parcours. */
void insertAfter(DNode_t *p, DNode_t *pNew)
{
    pNew->pNext = p->pNext;                 /* 1. la suite de p        */
    pNew->pPrev = p;                        /* 2. le prédécesseur      */
    if (p->pNext != NULL) p->pNext->pPrev = pNew;  /* 3. le successeur */
    p->pNext = pNew;                        /* 4. enfin p           */
}

/* Supprimer pOld — O(1) si on a déjà le nœud. */
void unlink(DList_t *pList, DNode_t *pOld)
{
    if (pOld->pPrev != NULL) pOld->pPrev->pNext = pOld->pNext;
    else                     pList->pHead = pOld->pNext;   /* c'était la tête */

    if (pOld->pNext != NULL) pOld->pNext->pPrev = pOld->pPrev;
    else                     pList->pTail = pOld->pPrev;   /* c'était la queue */

    free(pOld);
}

La liste « à moitié double »

Une erreur classique : mettre à jour pNext mais oublier pPrev. Le parcours avant fonctionne, le parcours arrière saute un nœud — et le bug n'apparaît qu'à la première suppression. Écris toujours les deux affectations dans la même fonction, et vérifie sur une liste de trois nœuds dans les deux sens.

09
circulaire

Circulaire : le dernier pointe sur le premier

Une seule ligne change tout : au lieu de C->pNext = NULL, on écrit C->pNext = pHead. Il n'y a plus de NULL nulle part — donc plus de fin, et un parcours naïf qui ne s'arrête jamais.

La règle de la circulaire

Trois conséquences, à connaître par cœur : 1. il n'y a plus de NULL, donc plus de condition d'arrêt naturelle ; 2. le parcours doit être borné par un compteur ou par un retour sur la tête, avec un do … while ; 3. la queue donne accès à la tête (pTail->pNext), donc un seul pointeur suffit pour insérer aux deux bouts en O(1).

File de messages critiquele consommateur et le producteur tournent sur les mêmes maillons, sans réallocation
Deux fautes qui font tourner en rond

La condition d'arrêt : garder while (pFlow != NULL) sur une circulaire = boucle infinie, programme bloqué, watchdog qui redémarre la carte. La liste d'un seul nœud : A->pNext = A. Un while (pFlow->pNext != pHead) fonctionne, mais un while (pFlow->pNext != NULL) non — et un parcours « tant qu'il y a un suivant » ne verra jamais la fin.

liste contre tableau

Liste ou tableau : complexités

Aucune des deux structures n'est meilleure : elles ne répondent pas aux mêmes questions. Le tableau gagne sur l'accès direct et la localité mémoire ; la liste gagne sur l'insertion et la suppression à une position déjà atteinte.

Comment choisir, en trois questions

1. Est-ce que j'accède souvent par indice ? → tableau. 2. Est-ce que j'insère ou supprime souvent, à des positions déjà atteintes, ou en tête ? → liste. 3. Est-ce que je connais la taille maximale et qu'elle tient en mémoire ? → tableau, il est plus simple et plus rapide. La liste est faite pour ce qui grandit, rétrécit et se réordonne sans cesse.

Le coût caché : la fragmentation

Chaque malloc prend un bloc et laisse un peu d'en-tête de gestion. Après mille ajouts et retraits, le tas est parsemé de trous : un malloc de 32 octets peut échouer alors qu'il reste 10 ko libres, mais dispersés. Un tableau de taille fixe ne connaît pas ce problème. Sur un système embarqué qui tourne des semaines, on préfère souvent un tampon circulaire de taille fixe à une liste de longueur variable.

200 000 lectures aléatoires, 3 insertions : quelle structure ?
Le tableau. Les lectures aléatoires sont en O(1) contre O(n) pour la liste : le rapport est de plusieurs ordres de grandeur, et trois insertions ne pèsent rien en face. La liste ne gagne que si les insertions/suppressions sont fréquentes et les positions déjà connues.

Trois outils qui voient ces fautes

gcc -Wall -Wextra -Werror -fsanitize=address,undefined attrape l'usage après free, le double free, les débordements et les fuites à l'exécution. valgrind --leak-check=full fait le même travail, plus lentement, sur Linux. Et sur un microcontrôleur, la seule défense est la relecture : chaque malloc a-t-il son free ? chaque chemin d'erreur libère-t-il ce qu'il a alloué ?

Le piège du piège : le nœud détaché

Supprimer un nœud, ce n'est pas seulement l'enlever de la chaîne : c'est aussi le libérer. Un pFlow->pNext = pOld->pNext; sans free(pOld) donne une liste apparemment correcte — elle s'affiche, elle se parcourt — mais chaque suppression fuit 16 octets. Sur 10 000 cycles, cela fait 160 ko perdus, et le programme meurt sans explication. C'est la faute la plus difficile à voir à l'œil nu.

applications

Là où la liste chaînée est la bonne réponse

FIFO, LIFO, table de hachage, listes d'adjacence de graphes, tampons de communication : cinq usages qui reviennent en embarqué et qui reposent tous sur les mêmes trois gestes.

FIFO : ajouter en queue, retirer en tête

C'est l'exercice 3.1 du cours. Un FIFO (First In, First Out) ajoute en queue et retire en tête : le premier arrivé est le premier servi. La liste n'existe que par pList, et la liste vide s'écrit pList == NULL — aucun nœud sentinelle.

ex3-1_fifo.c
typedef struct Data_s
{
    int    sensorNumber;
    double sensorValue;
    long   time;
    struct Data_s *pNext;
} Data_t;

Data_t *createFIFO(void) { return NULL; }   /* une liste vide n'a aucun nœud */

bool put(Data_t **ppList, Data_t newElement)     /* ajouter en queue : O(n) */
{
    Data_t *pNew = malloc(sizeof *pNew);
    if (pNew == NULL) return false;              /* plus de mémoire : liste intacte */

    *pNew = newElement;                          /* recopie des champs */
    pNew->pNext = NULL;

    if (*ppList == NULL) { *ppList = pNew; }     /* liste vide : cas à part */
    else
    {
        Data_t *pFlow = *ppList;
        while (pFlow->pNext != NULL) pFlow = pFlow->pNext;
        pFlow->pNext = pNew;
    }
    return true;
}

bool get(Data_t **ppList, Data_t *pElement)      /* retirer en tête : O(1) */
{
    if (*ppList == NULL) return false;           /* rien à retirer */

    Data_t *pOld = *ppList;
    pElement->sensorNumber = pOld->sensorNumber;    /* on copie AVANT de libérer */
    pElement->sensorValue  = pOld->sensorValue;
    pElement->time         = pOld->time;
    pElement->pNext        = NULL;                  /* jamais pOld->pNext */
    *ppList = pOld->pNext;                          /* la tête devient la suivante */
    free(pOld);
    return true;
}
Le piège exact de get

Recopier l'élément avec *pElement = *pOld; copie aussi pNext. L'élément rendu à l'appelant pointe alors sur un nœud qui vient d'être libéré : le prochain accès à ce champ est un comportement indéfini. Il faut soit recopier les champs un par un, soit remettre pElement->pNext = NULL; après la copie. Et toujours free après la recopie, jamais avant.

LIFO : la même liste, prise par l'autre bout

Un LIFO (Last In, First Out, une pile) ajoute et retire en tête : push = insertHead, pop = suppression de la tête. Les deux opérations sont en O(1), et il n'y a pas besoin de parcourir la liste — c'est la structure la plus rapide du chapitre. C'est la pile d'appels, la fonction undo, l'analyse d'expressions.

Le détail embarqué : tampon ou liste ?

Une liste chaînée grandit sans limite, ce qui est vital sur un PC et dangereux sur un microcontrôleur : si un producteur va plus vite que le consommateur, le tas se remplit et malloc renvoie NULL. Un tampon circulaire de taille fixe, avec deux index et un tableau, a un coût mémoire borné et prévisible — c'est pour cela qu'on le préfère dans les pilotes de communication. La liste reste le bon choix quand on ne peut pas majorer le nombre d'éléments.

mémo & checklist

Mémo et checklist

Six lignes de code, sept coûts et huit réflexes à retenir.

Les gestes, en six lignes

  • Tête : pNew->pNext = pBegin; pBegin = pNew;
  • Après p : pNew->pNext = p->pNext; p->pNext = pNew;
  • Queue : pFlow->pNext = pNew; avec pNew->pNext = NULL
  • Supprimer : pOld = pFlow->pNext; pFlow->pNext = pOld->pNext; free(pOld);
  • Parcourir : for (p = h; p; p = p->pNext)
  • Tout libérer : sauver pNext, free, puis avancer

Les coûts à réciter

  • accès par indice : O(n)
  • recherche : O(n), même triée
  • insertion en tête : O(1)
  • insertion en queue : O(n), O(1) avec pTail
  • suppression en tête : O(1)
  • suppression d'un nœud connu : O(n) en simple, O(1) en double
  • inversion complète : O(n) temps, O(1) mémoire

Les huit réflexes

  • La liste vide est-elle testée avant tout pFlow->pNext ?
  • Chaque malloc a-t-il son test de NULL et son free ?
  • Ai-je écrit pNew->pNext = NULL; après le malloc ?
  • L'ordre est-il « relier d'abord, déplacer la tête ensuite » ?
  • Le free vient-il après le recâblage ?
  • pTail (et pHead) sont-ils à jour après chaque opération ?
  • Est-ce que je modifie la tête dans une fonction ? Alors il faut **.
  • Le parcours utilise-t-il pFlow, jamais pBegin ni le paramètre ?
La méthode en trois temps

Face à un exercice de listes, dessine toujours les trois mêmes choses : 1. la liste avant l'opération, avec les adresses ; 2. la liste après, avec les mêmes adresses ; 3. les flèches qui changent entre les deux. Le code se déduit alors du dessin, et l'ordre des affectations devient évident : on ne casse jamais un lien avant d'en avoir posé un autre.

À retenir

Une liste chaînée est un enchaînement de propriétaires : chaque nœud possède l'adresse du suivant, et la tête possède la liste. Trois questions suffisent : qui est la tête ? quel lien je casse ? où est le free ?

Insérer A, B, C en tête, puis supprimer la tête deux fois : que reste-t-il ?
On insère dans l'ordre A, B, C : chaque insertion prend la tête, donc la liste devient C → B → A → NULL. Deux suppressions de tête retirent C puis B : il reste A seul, avec pBegin = 0x3000 et A->pNext = NULL. Une troisième suppression viderait la liste et mettrait pBegin à NULL ; une quatrième doit renvoyer false sans rien déréférencer.

Exercices 1.71.81.11
01
l'idée

Une structure regroupe des membres sous un seul nom

Une structure est un type composé : elle nomme un ensemble de membres de types différents et les range dans un seul objet. Déclarer le type ne réserve aucune mémoire ; déclarer une variable réserve sizeof octets.

À retenir

Un tableau range des éléments de même type, numérotés par un indice. Une structure range des membres de types différents, nommés : on y accède par ., jamais par un indice. Les deux sont des types composés, mais seul le tableau est homogène.

declaration.c
struct Point {
    int x;
    int y;
};

struct Point p1 = {12, 34};           /* initialisation par position */
struct Point p2 = {.y = 7, .x = 3};   /* désignée, C99 */
p1.x = 10;                            /* accès au membre */
int somme = p1.x + p2.y;              /* 10 + 7 = 17 */
Ce que chaque ligne déclare
écriturece que c'estmémoire
struct Point { … };un type, un modèleaucune
struct Point p1;une variable de ce type8 octets
p1.xle membre x, une lvalue intdans les 8 octets
struct Point p2 = {3, 7};une seconde variable, initialisée8 octets
La règle

Le point-virgule après } est obligatoire : struct Point { int x; int y; }; est une déclaration, pas un bloc. Le nom du type s'écrit struct Point tant qu'aucun typedef n'a été fait (§ 3). L'initialisation par position suit l'ordre de déclaration : {12, 34} donne x = 12, y = 34.

La structure du cours : struct tm

struct tm est la structure de l'exercice 1.7 : neuf int, donc 36 octets mesurés, qui décomposent un instant en champs lisibles. Chaque champ a sa convention, et c'est là que se trouvent les erreurs.

temps.c
struct tm {
    int tm_sec;     /* secondes : 0-59 */
    int tm_min;     /* minutes : 0-59 */
    int tm_hour;    /* heures : 0-23 */
    int tm_mday;    /* jour du mois : 1-31 */
    int tm_mon;     /* mois depuis janvier : 0-11 */
    int tm_year;    /* années depuis 1900 */
    int tm_wday;    /* jour de la semaine : 0 = dimanche */
    int tm_yday;    /* jour depuis le 1er janvier */
    int tm_isdst;   /* heure d'été : 1, 0 ou -1 */
};

time_t now = time(NULL);
struct tm t = *localtime(&now);     /* localtime rend un pointeur */
printf("%02d.%02d.%04d\n",
       t.tm_mday, t.tm_mon + 1, t.tm_year + 1900);
Note

tm_mon vaut 0 pour janvier : on affiche tm_mon + 1. tm_year compte depuis 1900 : on affiche tm_year + 1900. tm_wday vaut 0 pour dimanche. localtime renvoie l'adresse d'une structure interne : *localtime(&now) en copie le contenu, localtime(&now)->tm_hour lit un champ directement.

Le piège

struct Point p; laisse x et y non initialisés : leur valeur est indéterminée, pas zéro. Pour partir de zéro, écrire struct Point p = {0}; met les membres non cités à zéro. Et hors déclaration, p = {12, 34}; n'est pas du C : il faut p = (struct Point){12, 34}; (littéral composé, C99).

02
la mémoire

Les membres sont contigus, avec des trous d'alignement

Une structure est un bloc d'octets contigus. Les membres suivent l'ordre de déclaration, mais le compilateur insère du bourrage pour que chaque membre commence à une adresse multiple de son alignement. sizeof donne la taille totale, bourrage compris ; offsetof donne le décalage d'un membre.

Les tailles et les décalages du tableau suivant sont mesurés avec gcc 13.2 sur x86-64, avec sizeof et offsetof. Ils ne sont pas universels : un autre compilateur, un autre modèle de données ou une autre architecture peut changer le bourrage.

La règle

Chaque membre commence à une adresse multiple de son alignement : 4 pour un int, 8 pour un double, 2 pour un int16_t. La taille totale est un multiple de l'alignement le plus exigeant de la structure, d'où le bourrage final. sizeof(T) inclut ce bourrage ; offsetof(T, membre) donne le décalage en octets et demande <stddef.h>.

Ne jamais additionner les membres

char c; int i; char d; fait 12 octets, pas 6. La somme des tailles des membres ne donne la taille d'une structure que si aucun alignement ne l'agrandit, ce qui est rare. Utiliser sizeof pour la taille et offsetof pour un décalage : ce sont les deux seules valeurs portables.

03
les types

Nommer, énumérer, superposer : typedef, enum, union

Trois outils complètent struct. typedef donne un nom à un type, enum donne des noms à des constantes entières, union fait partager la même mémoire à plusieurs membres. Le carnet d'adresses de l'exercice 1.8 utilise les deux premiers.

types.c
typedef struct { int16_t x; int16_t y; } Point_t;   /* Point_t, sans le mot struct */
typedef char Name_t[20];                          /* un type tableau */
typedef enum {
    eClass_E1a, eClass_E1bd, eClass_E2a,
    eClass_E2bd, eClass_E3_EL, eClass_E3_EN
} Class_t;

typedef union {
    uint32_t mot;        /* les 4 octets d'un coup */
    uint8_t  octets[4];  /* ou octet par octet */
} Mesure_t;
Les trois outils, côte à côte

typedef : un nom, pas un nouveau type

typedef struct { … } Point_t; déclare une structure anonyme et lui donne le nom Point_t. Ensuite, Point_t p; remplace struct Point p;. typedef char Name_t[20]; est plus subtil : Name_t est un type tableau, donc Name_t n; déclare char n[20], et sizeof(Name_t) vaut 20.

La règle

Un typedef se lit comme une déclaration : le nom typé prend la place de la variable. typedef char Name_t[20]; se lit « Name_t est un tableau de 20 char ». Il ne crée aucun type distinct : le compilateur ne distingue pas Name_t de char[20].

enum : des constantes nommées

Les énumérateurs valent 0, 1, 2… dans l'ordre de déclaration, sauf valeur explicite. Class_t donne ainsi eClass_E1a == 0 et eClass_E3_EN == 5. Le type de l'énumération est ici un int de 4 octets ; le standard laisse au compilateur le choix d'un type capable de contenir toutes les valeurs.

enum.c
enum { eNameLen = 20, eAddressLen = 40, eMaxStudents = 30 };
enum { eNbrOfCorners = 4 };

static char const *const cClass[] = {
    "E-1a", "E-1bd", "E-2a", "E-2bd", "E-3EL", "E-3EN"
};
printf("%s\n", cClass[s.currentClass]);   /* enum -> texte */

union : les membres partagent la même adresse

Tous les membres d'une union commencent à l'offset 0 et se superposent. Mesure_t fait 4 octets : écrire mot remplit les quatre octets, lire octets[i] les relit un par un.

union.c
Mesure_t m;
m.mot = 0x12345678u;
printf("%02X %02X %02X %02X\n",
       m.octets[0], m.octets[1], m.octets[2], m.octets[3]);
/* 78 56 34 12 sur x86-64 : petit-boutisme */
Le piège

Relire un membre différent de celui qui vient d'être écrit réinterprète les octets : le résultat dépend de l'implémentation et de l'ordre des octets. Ce n'est pas une conversion, c'est une lecture de la même mémoire. Pour convertir réellement, affecter à un membre du bon type ; pour un registre, l'union reste l'outil adapté mais il faut connaître le boutisme de la cible.

Note

enum et union acceptent aussi un nom de type : enum Class_e { … }, typedef union Mesure_u { … } Mesure_t;. Le cours garde les deux formes : typedef enum { … } Class_t; pour les classes, typedef union { … } Mesure_t; pour les mesures.

04
tableaux

Un tableau de structures est un tableau d'objets complets

Les éléments sont contigus, chacun avec ses membres et son bourrage. Le pas d'un élément à l'autre est sizeof(T) : 16 octets pour le petit Etudiant ci-dessous, 132 octets pour le Student_t du carnet.

tableau.c
typedef struct { char nom[12]; int note; } Etudiant;

Etudiant tab[3] = {{"Bykov", 4}, {"Luthi", 5}, {"Sauber", 5}};
size_t const n = sizeof tab / sizeof tab[0];      /* 3 */

for (size_t i = 0; i < n; i++) {
    printf("%s : %d\n", tab[i].nom, tab[i].note);
}

La règle

sizeof tab / sizeof tab[0] ne donne le nombre d'éléments que dans la portée où le tableau est déclaré. Passé à une fonction, tab devient un pointeur : sizeof vaut 8 et le nombre d'éléments doit être passé séparément. Le nombre utilisé (count ou n) et la capacité (30, 3…) sont deux choses différentes.

Le piège

for (i = 0; i <= n; i++) lit tab[n], hors du tableau : comportement indéfini, souvent silencieux. La borne est i < n. Et pour le carnet, un élément de Student_t avance de 132 octets (0x84), pas de 16 : l'adresse de studentsGE[i] vaut base + 132·i.

05
imbrication

Une structure imbriquée est un membre, pas un pointeur

Student_t contient une Address_t. Cette adresse est stockée dans l'étudiant, à l'offset 44 : les 88 octets de l'adresse font partie des 132 octets de l'étudiant. Il n'y a ni allocation ni indirection.

imbrique.c
typedef struct {
    char street[40];
    int  houseNbr;
    int  zipCode;
    char city[40];
} Address_t;                              /* 88 octets */

typedef struct {
    char      firstName[20];
    char      lastName[20];
    Class_t   currentClass;
    Address_t homeAddress;                /* 88 octets, en place */
} Student_t;                              /* 132 octets */

Student_t s;
strcpy(s.homeAddress.city, "Fribourg");
printf("%s\n", s.homeAddress.city);

Student_t const *pS = &s;
printf("%s\n", pS->homeAddress.city);     /* flèche puis points */
Décalages dans Student_t (gcc 13.2, x86-64)
expressionoffsettype

s.lastName20char[20]

s.homeAddress44Address_t (88 octets)
s.homeAddress.street44char[40]
s.homeAddress.houseNbr84int

La règle

L'imbrication ne change pas la taille : 44 + 88 = 132. Les décalages s'additionnent : offsetof(Student_t, homeAddress) + offsetof(Address_t, city) vaut 44 + 48 = 92. L'accès se fait par une chaîne de ., et par -> seulement sur le premier maillon si l'on part d'un pointeur : pS->homeAddress.city.

Le piège

s.homeAddress->city ne compile pas : homeAddress est une structure, pas un pointeur. pS.homeAddress ne compile pas non plus : pS est un pointeur, il faut pS->homeAddress. Enfin s->homeAddress.city est faux : s n'est pas un pointeur.

Note

L'initialisation désignée simplifie les structures profondes : Student_t s = {.firstName = "Linus", .lastName = "Torvalds", .currentClass = eClass_E1a, .homeAddress = {.city = "Fribourg"}};. Les membres non cités sont mis à zéro, les tableaux de caractères compris.

06
pointeurs

p->x déréférence et accède en un seul geste

Un pointeur de structure contient l'adresse d'une structure entière, pas celle d'un membre. p->x est exactement (*p).x : déréférencer, puis prendre le membre. Les parenthèses sont obligatoires, car . est plus prioritaire que *.

La règle de priorité

. et -> ont la priorité la plus haute, * vient après. Donc *p.x se lit *(p.x) : on cherche x dans le pointeur, ce qui n'a pas de sens. Il faut (*p).x ou p->x. Le pointeur lui-même se lit avec sizeof(p) = 8 ; la structure visée avec sizeof(*p) = 4.

const struct : lecture seule

const.c
Point_t const *pc = &pt;   /* la structure visée est const */
printf("%d\n", pc->x);      /* lecture permise */
pc->x = 0;                 /* error: assignment of member 'x' in read-only object */

Point_t *const pfixe = &pt;/* le pointeur est const */
pfixe->x = 5;              /* écriture permise */
pfixe = &autre;            /* error: assignment of read-only variable 'pfixe' */
Le piège

Point_t const *p et Point_t *const p ne protègent pas la même chose. Le premier interdit d'écrire p->x mais permet p = &autre. Le second permet p->x = 5 mais interdit de réaffecter p. Pour tout protéger : Point_t const *const p.

Note

Un pointeur de structure null se teste avant tout accès : if (p != NULL) { p->x = 0; }. Un pointeur non initialisé contient une adresse quelconque : p->x est alors un comportement indéfini, pas une erreur de compilation.

07
copie

a = b copie les membres ; == et memcmp ne comparent pas ce qu'on croit

L'affectation d'une structure copie tous ses membres, tableaux internes compris. Mais deux structures ne se comparent pas avec ==, et memcmp compare aussi le bourrage, dont le contenu n'est pas défini.

Laboratoire · copie ou pointeur
modifier la copie ne touche pas l'original
6 états
copie.c
Point_t a = {1, 2};
Point_t b = a;        /* copie des 4 octets : deux objets */
b.x = 9;              /* a.x reste 1 */

Point_t *q = &a;      /* q contient l'adresse de a */
q->x = 9;             /* a.x devient 9 */

/* a == b ne compile pas :
   invalid operands to binary == (have 'Point_t' and 'Point_t') */
La règle

Une affectation a = b copie la valeur de chaque membre : les tableaux internes sont copiés, contrairement aux tableaux ordinaires qu'on ne peut pas affecter. Les pointeurs internes sont copiés tels quels : les deux structures pointent alors vers la même cible (copie superficielle, § 11).

memcmp et le bourrage

memcmp(&a, &b, sizeof a) compare tous les octets, y compris ceux du bourrage. Deux structures dont les membres sont égaux peuvent donc différer, car le bourrage n'a pas de valeur définie.

memcmp.c
struct Mixte { char c; int i; char d; };

struct Mixte a, b;
memset(&a, 0xAA, sizeof a);      /* remplit aussi le bourrage */
memset(&b, 0x55, sizeof b);
a.c = b.c = 'A';
a.i = b.i = 5;
a.d = b.d = 'z';

printf("%d\n", memcmp(&a, &b, sizeof a));   /* 1 */
Ce que montre la sortie

Les membres sont identiques — c, i et d ont la même valeur — et pourtant memcmp renvoie une valeur non nulle : les octets de bourrage diffèrent (0xAA contre 0x55). Le résultat exact de memcmp n'est pas spécifié au-delà de son signe ; seule compte ici l'information « non nul ».

Le piège

Pour comparer deux structures, comparer membre par membre (a.x == b.x && a.y == b.y) ou, pour des chaînes, avec strcmp. Si memcmp est vraiment nécessaire, remplir d'abord tous les octets (memset puis affectation des membres) et ne pas passer par une affectation de structure entre-temps. Pour des flottants, memcmp distingue même 0.0 et -0.0.

08
fonctions

Par valeur on copie, par pointeur on agit sur l'original

En C, tous les arguments sont passés par valeur. Une fonction qui reçoit une structure en reçoit une copie ; pour modifier celle de l'appelant, elle doit recevoir son adresse. Un tableau, lui, devient toujours un pointeur.

fonctions.c
/* lecture seule : pointeur const, aucune copie */
void printStudents(Student_t const table[], size_t count)
{
    if (count == 0u) {
        printf("No student in table available yet!\n");
        return;
    }
    for (size_t i = 0u; i < count; i++) {
        Student_t const *const pS = &table[i];
        printf("%u : %s %s\n", (unsigned)i,
               pS->firstName, pS->lastName);
    }
}

/* écriture : le compteur est mis à jour par adresse */
bool addStudent(Student_t table[], size_t *pCount,
                Student_t const *pNew)
{
    if (*pCount >= eMaxStudents) {
        return false;               /* tableau plein */
    }
    table[*pCount] = *pNew;         /* copie de tous les champs */
    (*pCount)++;
    return true;
}

La règle

Student_t table[] dans une liste de paramètres équivaut à Student_t *table : sizeof table vaut 8 dans la fonction, pas 30 × 132. La taille doit donc être passée séparément. Pour un compteur que la fonction doit modifier, on passe son adresse : &count, et on écrit (*pCount)++.

Le piège

*pCount++ incrémente le pointeur, puis le déréférence : le compteur n'est pas mis à jour et pCount pointe ailleurs. Les parenthèses sont obligatoires : (*pCount)++. Même piège avec *table[i].note++, qui se lit *(table[i].note++).

Retourner une structure

Une fonction peut renvoyer une structure par valeur : le résultat est une copie, construite par la fonction. L'exercice 1.7 le fait avec struct tm.

retour.c
struct tm lastSecondOfTime32(void)
{
    time_t const cMax = (time_t)INT_MAX;   /* 2^31 - 1 */
    return *localtime(&cMax);              /* copie de la structure */
}

/* appel */
struct tm t = lastSecondOfTime32();
Note

Le retour par valeur copie la structure, ce qui peut coûter cher pour 132 octets. Les compilateurs optimisent souvent ce cas, mais le contrat du langage reste une copie. Ne jamais renvoyer l'adresse d'une variable locale : elle disparaît au retour de la fonction.

09
exercices 1.7 et 1.11

Aire et périmètre d'un Rectangle avec le pointeur pC

Le couple Point/Rectangle est l'application de l'exercice 1.11 ; l'exercice 1.7 est la structure struct tm présentée au § 1. Les deux suivent la même règle : les membres sont contigus, et un pointeur vers le premier coin permet de parcourir les quatre points.

rectangles.c
enum { eNbrOfCorners = 4 };

typedef struct { int16_t x; int16_t y; } Point_t;          /* 4 octets */
typedef struct {
    Point_t corners[eNbrOfCorners];                        /* 16 octets */
    int32_t area;                                          /*  4 octets */
} Rectangle_t;                                             /* 20 octets */

/* d) aire : coins 0 et 2 opposés, côtés parallèles aux axes */
void computeArea(Rectangle_t *pRect)
{
    Point_t const *pC = pRect->corners;   /* = &corners[0] */
    int32_t const w = pC[2].x - pC[0].x;
    int32_t const h = pC[2].y - pC[0].y;
    pRect->area = (w < 0 ? -w : w) * (h < 0 ? -h : h);
}

int32_t computePerimeter(Rectangle_t const *pRect)
{
    Point_t const *pC = pRect->corners;
    int32_t const w = pC[2].x - pC[0].x;
    int32_t const h = pC[2].y - pC[0].y;
    return 2 * ((w < 0 ? -w : w) + (h < 0 ? -h : h));
}

/* coins (0,0) (0,10) (10,10) (10,0) : aire 100, périmètre 40 */

La règle

pC est un Point_t const * : il avance de sizeof(Point_t), soit 4 octets. pC[2] est donc corners[2], et pC[2].x - pC[0].x donne la largeur quand les coins 0 et 2 sont opposés. pRect->area et (*pRect).area désignent le même membre.

Le piège

La formule de l'aire suppose des côtés parallèles aux axes et les coins 0 et 2 opposés. Pour un rectangle quelconque, il faut calculer les minima et maxima des quatre points, ou utiliser des vecteurs. Et pC ne doit pas être confondu avec pRect : le premier vise un coin, le second le rectangle entier.

Note

Dans rectangles.c, le tri par aire copie les structures entières : Rectangle_t const tmp = table[i]; puis les deux affectations. Un échange de 20 octets, pas d'un seul champ. La comparaison porte sur table[i].area.

10
exercice 1.8

Ex 1.8 : un tableau de structures, un compteur, une recherche

Le carnet d'adresses range 30 étudiants au maximum, dont on connaît le nombre utilisé. L'ajout copie une structure entière ; la recherche parcourt le tableau et compare les noms avec strcmp.

etudiants.c
enum { eNameLen = 20, eAddressLen = 40, eMaxStudents = 30 };
typedef char Name_t[eNameLen];
typedef char AddressName_t[eAddressLen];

typedef enum {
    eClass_E1a, eClass_E1bd, eClass_E2a,
    eClass_E2bd, eClass_E3_EL, eClass_E3_EN
} Class_t;

typedef struct {
    AddressName_t street;
    int houseNbr;
    int zipCode;
    AddressName_t city;
} Address_t;                          /* 88 octets */

typedef struct {
    Name_t   firstName;               /* char[20] */
    Name_t   lastName;                /* char[20] */
    Class_t  currentClass;            /* enum      */

La règle

La capacité est eMaxStudents = 30 ; le nombre utilisé est count, mis à jour par adresse. Les indices valides vont de 0 à count - 1. table[*pCount] = *pNew; copie tous les champs, tableaux de caractères compris : c'est une affectation de structure, pas un memcpy de pointeurs.

Le piège

strcmp compare des octets, pas l'alphabet français : « Émile » passe après « Zoé » parce que le premier octet de É (0xC3) dépasse Z (0x5A). Et strcpy dans char[20] accepte au plus 19 caractères plus le terminateur : au-delà, il déborde sur le champ voisin.

Note

Après le tri à bulles sur lastName, l'ordre des octets donne Bykov, Luthi, Sauber, Stallman, Torvalds, Wawrinka. Le tri copie les structures entières : Student_t const tmp = table[i];, puis les deux affectations. La comparaison porte sur strcmp(...) < 0.

La copie superficielle

Une structure qui contient un char * ne contient pas le texte : elle contient une adresse. L'affectation copie l'adresse, et les deux structures partagent alors le même tampon.

superficielle.c
typedef struct { char *nom; int note; } Fiche;

char tampon[] = "Linus";
Fiche a = {tampon, 5};
Fiche b = a;              /* b.nom == a.nom : même tampon */

b.nom[0] = 'l';
printf("%s / %s\n", a.nom, b.nom);   /* linus / linus */
Le piège

Pour que la copie soit indépendante, le texte doit être dans la structure (char nom[20]) ou copié explicitement (malloc + strcpy). Avec un char *, modifier b.nom[0] modifie aussi ce que lit a.nom, puisqu'il n'y a qu'un seul tampon.

Les outils qui voient les fautes

gcc -std=c11 -Wall -Wextra -Werror -pedantic attrape les prototypes, les conversions et les sizeof suspects. -fsanitize=address,undefined attrape les débordements de tableaux et de chaînes à l'exécution. Un champ non initialisé se voit avec -fsanitize=memory (Clang) ou en initialisant toute structure à {0}.

Huit réflexes

  • sizeof et offsetof, jamais une somme de membres.
  • Initialiser toute structure : = {0} ou désignée.
  • Accès : s.m, p->m, (*p).m.
  • Lecture seule : T const *p.
  • Copie : a = b ; comparaison : membre par membre.
  • Tableau en paramètre : passer n avec.
  • Compteur modifié : passer &count, écrire (*p)++.
  • Chaîne : char[20] = 19 caractères + '\0'.
La checklist
  • Déclarer une structure, l'initialiser par position et par désignation, accéder à ses membres.
  • Calculer sizeof et les offsets d'une structure avec bourrage.
  • Choisir entre struct, union et enum, et nommer un type avec typedef.
  • Parcourir un tableau de structures et y chercher un élément avec strcmp.
  • Accéder à une structure imbriquée par . et ->.
  • Écrire p->x, (*p).x et const T *p sans confondre.
  • Expliquer pourquoi memcmp ne compare pas deux structures de façon fiable.
  • Passer une structure par valeur, par pointeur, et la retourner par valeur.
  • Refaire l'aire et le périmètre d'un Rectangle_t avec pC.
  • Ajouter et rechercher un étudiant dans le carnet de 30 places.
À retenir

Une structure est un type, pas une variable : sa taille est sizeof, ses décalages sont offsetof, et son affectation copie les membres. Le reste — tableaux, pointeurs, fonctions — n'est que l'application de ces trois règles.

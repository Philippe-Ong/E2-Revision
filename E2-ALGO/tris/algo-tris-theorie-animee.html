Exercices 1.5
01
le problème

Comparer et échanger : deux opérations suffisent

Trier, c'est ranger n éléments selon une relation d'ordre, en n'utilisant que deux gestes : comparer deux éléments et les déplacer. Toute la théorie — complexité, stabilité, mémoire — se déduit du nombre de fois qu'on fait ces deux gestes.

À retenir

Un tri est une machine à deux boutons. Le bouton « comparer » ne dit que plus petit, égal ou plus grand ; le bouton « échanger » déplace deux cases. Un algorithme de tri n'est rien d'autre qu'un programme de boutons : combien de comparaisons, combien d'échanges, dans quel ordre. Deux tris qui font les mêmes gestes dans un ordre différent peuvent avoir le même résultat et des coûts du simple au centuple.

Trois propriétés, trois questions

Avant d'écrire une boucle, pose trois questions. Elles reviennent dans tous les exercices et dans tous les QCM.

La borne à connaître

Aucun tri par comparaison ne peut garantir moins de log₂(n!) comparaisons, soit environ n log₂ n − 1,44 n. C'est pour cela que O(n log n) est la meilleure classe possible pour un tri généraliste : le tri fusion et le tri rapide l'atteignent, les tris quadratiques en sont très loin. La borne est une information, pas une promesse : elle ne dit rien du cas moyen d'un algorithme donné.

« En place » ne veut pas dire « stable »

Ce sont deux axes indépendants. Le tri par sélection est en place et instable ; le tri fusion est stable et pas en place ; le tri par insertion est les deux à la fois ; le tri rapide est en place (seule la pile de récursion s'ajoute) mais instable. Une question d'examen peut porter sur un seul des deux axes : lis bien le mot.

Le tableau témoin de toute la page

Tous les laboratoires utilisent le même tableau de sept valeurs : 5, 1, 4, 2, 8, 7, 3. Il a été choisi parce qu'il n'est ni trié, ni inversé, et qu'il contient neuf inversions — assez pour voir plusieurs passes, assez peu pour suivre à la main.

Une inversion est une paire d'indices i < j telle que t[i] > t[j]. Il y en a exactement neuf ici :

Les compteurs de cette page

Chaque laboratoire affiche deux compteurs : les comparaisons (chaque évaluation d'un < entre deux éléments) et les écritures (chaque affectation d'un élément ; un échange classique en compte 3). Ils sont produits par la même implémentation que le code C affiché, exécutée sur le témoin, et vérifiés par un banc de test. Le total doit toujours valoir : 1, 2, 3, 4, 5, 7, 8 à la fin.

02
ex. 1.5 · A8

Tri à bulles : le plus grand remonte, passe après passe

À chaque passe, on compare les voisins et on échange les paires inversées. Le plus grand élément « fait des bulles » jusqu'à la fin du tableau ; on recommence tant qu'une passe a échangé quelque chose.

À retenir

Passe le tableau au peigne, de gauche à droite. Chaque fois que deux voisins sont à l'envers, tu les remets dans l'ordre. À la fin d'une passe, la plus grande valeur est forcément arrivée tout à droite — comme une bulle qui remonte. La passe suivante n'a plus besoin d'aller jusqu'au bout : les dernières cases sont déjà définitives.

Voici exactement l'algorithme de l'énoncé 1.5, en C11 : la boucle repeat … until s = 0 devient un do … while, et s compte les permutations de la passe.

tri-a-bulles.c
/* Tri à bulles du cours (Ex. 1.5) : repeat ... until s = 0.
   Renvoie le nombre total de permutations. */
uint32_t triABulles(int16_t t[], size_t n)
{
    uint32_t permutations = 0u;
    uint32_t s;

    do {
        s = 0u;                        /* le compteur repart à zéro   */
        for (size_t i = 1u; i < n; i++) {
            if (t[i] < t[i - 1u]) {    /* paire de voisins inversée   */
                int16_t tmp = t[i];    /* échange : 3 écritures       */
                t[i] = t[i - 1u];
                t[i - 1u] = tmp;
                s++;
            }
        }
        permutations += s;
    } while (s != 0u);                 /* until s = 0 : on s'arrête   */

    return permutations;
}

À la fin de chaque passe, les cases vertes à droite sont définitives. Après la passe 1, le 8 est en dernière position ; après la passe 2, le 7 ; et ainsi de suite. La dernière passe ne fait que constater qu'il n'y a plus rien à échanger : s = 0 arrête tout.

La règle du cours
  • Parcourir de l'indice 1 à n − 1 ; si t[i] < t[i−1], échanger et incrémenter s.
  • Remettre s = 0 au début de chaque passe ; s'arrêter quand s == 0.
  • Le nombre de permutations est égal au nombre d'inversions : chaque échange de voisins en corrige exactement une.
  • Complexité : O(n²) dans le pire cas, O(n) si le tableau est déjà trié (une passe, n − 1 comparaisons, zéro échange).

Le s = 0 oublié

Si s n'est pas remis à zéro au début de chaque passe, le compteur garde les échanges de la passe précédente : la condition s != 0 reste vraie et la boucle ne s'arrête jamais. Le s = 0 est la première instruction du do, pas la dernière. Et ne confonds pas « N passes » avec « N comparaisons » : une passe fait n − 1 comparaisons.

La version sans drapeau

Sans le compteur s, il faut faire n − 1 passes, même si le tableau est déjà trié. Le résultat est identique, le coût ne l'est pas.

sans-drapeau.c
void triABullesSansDrapeau(int16_t t[], size_t n)
{
    for (size_t passe = 1u; passe < n; passe++) {
        for (size_t i = 1u; i < n; i++) {
            if (t[i] < t[i - 1u]) {     /* échange */
                int16_t tmp = t[i];
                t[i] = t[i - 1u];
                t[i - 1u] = tmp;
            }
        }
    }
}
Pourquoi le drapeau change tout

Sans drapeau, un tableau déjà trié coûte n(n−1)/2 comparaisons. Avec, il coûte n − 1. C'est exactement la définition d'un tri adaptatif. Le prix est une variable et un test par passe : négligeable.

Tortue et lièvre

Un grand élément qui part de la gauche traverse tout le tableau en une seule passe (le lièvre). Un petit élément qui part de la droite ne recule que d'une case par passe (la tortue) : c'est ce qui rend le tri à bulles lent sur les tableaux où un petit élément traîne à la fin. Le tri par insertion n'a pas ce défaut.

03
exemple 2 · complexité

Combien coûte une passe : la formule du cours

On ne chronomètre pas, on compte. La diapositive de complexité propose une convention : une passe coûte 4N − 2 pas, un échange en coûte 5, et le test d'arrêt 1. Avec P passes et I permutations, le coût total s'écrit en une ligne.

La formule

ct = P · (4N − 2) · t + 5 · I · t

  • s := 0 coûte 1t ; chaque tour de boucle 4t (incrément, deux accès, comparaison).
  • Un échange coûte 3t, plus 2t pour s := s + 1 : soit 5t par permutation.
  • P est le nombre de passes, I le nombre de permutations, N la taille du tableau.

Vérifie au moins une ligne à la main : pour la série de l'énoncé, 9 × 38 + 5 × 20 = 342 + 100 = 442. C'est le même calcul que l'exemple 1 du cours, avec des passes et des permutations en plus.

Avec les valeurs par défaut, tu obtiens le coût du tableau témoin : N = 7, P = 5, I = 9. Change P ou I pour voir basculer le coût d'un tableau déjà trié (une passe, zéro permutation) à un tableau inversé.

Les constantes dépendent de la convention

La diapositive ne donne que 3t pour un échange ; le 2t de s := s + 1 et le 4t du tour sont proposés, comme dans l'exemple 1. Deux corrigés peuvent donc afficher des constantes différentes sans se contredire. Ce qui ne change pas, c'est l'ordre de grandeur : O(N²) au pire, O(N) si le tableau est déjà trié.

Le piège du « nombre de passes »

Sur le témoin, le tri à bulles fait 5 passes mais 30 comparaisons : chaque passe compare 6 paires. Écrire « 5 passes donc 5 comparaisons » est faux. Et le nombre de passes dépend des données : c'est lui qui rend le coût variable, pas N seul.

04
insertion

Tri par insertion : on insère une carte à la fois

C'est le tri du joueur de cartes. La main gauche est triée ; on prend la carte suivante et on la glisse à sa place en décalant les cartes plus grandes d'une case vers la droite. Rien d'autre.

À retenir

La main gauche est triée. On prend la carte t[i] dans la main droite : c'est la clé. On la compare à la carte la plus à droite de la main gauche ; si elle est plus grande, elle glisse d'une case vers la droite et on recommence. Quand on trouve une carte plus petite (ou le bord de la main), on pose la clé devant elle. La main gauche a gagné une carte, toujours triée.

tri-insertion.c
void triInsertion(int16_t t[], size_t n)
{
    for (size_t i = 1u; i < n; i++) {
        int16_t cle = t[i];            /* la carte à insérer          */
        size_t j = i;

        while (j > 0u && cle < t[j - 1u]) {
            t[j] = t[j - 1u];          /* décalage vers la droite     */
            j--;
        }
        t[j] = cle;                    /* la clé trouve sa place      */
    }
}

Le préfixe vert grandit d'une case par insertion. La barre rouge est la valeur qui vient d'être décalée ; la case en pointillés est libre — elle contient encore une copie, mais la clé, gardée dans cle, va l'écraser. À la fin, 14 comparaisons et 15 écritures — contre 30 et 27 pour le tri à bulles sur le même tableau.

L'invariant, et pourquoi c'est stable

Avant chaque tour, les i premiers éléments sont triés et sont exactement les i plus petits du tableau. La comparaison est strictement inférieure (cle < t[j−1]) : une clé égale ne provoque pas de décalage, donc elle reste derrière la clé déjà en place. C'est ce < — et non ≤ — qui rend le tri stable.

Décaler, ce n'est pas échanger

La version naïve échange la clé avec son voisin à chaque inversion : 3 écritures par inversion. La version par décalage écrit une seule fois par inversion, plus une fois pour poser la clé. Sur le témoin : 15 écritures au lieu de 27 pour le tri à bulles. Sur un microcontrôleur, la différence se voit.

Complexité
  • Meilleur cas (déjà trié) : n − 1 comparaisons, n − 1 écritures — O(n).
  • Pire cas (ordre inverse) : n(n−1)/2 comparaisons et décalages — O(n²).
  • Moyenne : environ n²/4 comparaisons et décalages — O(n²), mais avec une petite constante.
Le tri des cas réels

C'est le tri utilisé pour les petites séries (moins de 16 à 32 éléments) et pour les données presque triées. Beaucoup de bibliothèques l'utilisent comme finition à l'intérieur d'un tri rapide ou d'un tri fusion : en dessous d'un certain seuil, ses constantes battent les algorithmes en n log n. On peut aussi diviser ses comparaisons par deux par recherche dichotomique dans le préfixe — mais les décalages, eux, ne bougent pas.

05
sélection

Tri par sélection : le minimum, puis un seul échange

À chaque passe, on cherche le minimum de la zone non triée et on l'échange avec la première case de cette zone. Un seul échange par passe — mais un balayage complet à chaque fois, quoi qu'il arrive.

À retenir

Tu as sept bulletins devant toi. Tu cherches le plus mauvais, tu le mets à gauche, et tu ne le regardes plus. Puis tu cherches le plus mauvais des six qui restent, tu le mets en deuxième position, et ainsi de suite. Tu ne déplaces presque rien — mais tu relis tout à chaque tour.

tri-selection.c
void triSelection(int16_t t[], size_t n)
{
    for (size_t i = 0u; i + 1u < n; i++) {
        size_t min = i;
        for (size_t j = i + 1u; j < n; j++) {
            if (t[j] < t[min]) {
                min = j;
            }
        }
        if (min != i) {                /* un seul échange par passe   */
            int16_t tmp = t[i];
            t[i] = t[min];
            t[min] = tmp;
        }
    }
}

Les comparaisons tombent toujours au même rythme : 21 pour sept éléments, soit n(n−1)/2, que le tableau soit trié ou non. Les échanges, eux, sont rares : 5 sur le témoin (15 écritures).

Le tri le plus prévisible
  • Comparaisons : toujours n(n−1)/2, dans tous les cas — meilleur, moyen, pire.
  • Échanges : au plus n − 1, donc au plus 3(n−1) écritures.
  • Complexité O(n²) partout, mémoire O(1), pas adaptatif, pas stable.

Pourquoi il n'est pas stable

L'échange est à longue distance : il saute par-dessus toutes les cases intermédiaires. Une clé égale peut donc passer de l'autre côté d'une autre clé égale. Le tableau suivant a huit étudiants, notés de 1 à 3 ; la lettre est leur ordre d'arrivée.

Huit étudiants, trois notes égales

On trie par note seulement. Les étudiants de même note doivent rester dans l'ordre a, b, c… : c'est ça, la stabilité.

La leçon du contre-exemple

Dans le tri par sélection, l'échange final déplace le minimum vers la gauche sans regarder les clés égales qu'il croise. Deux étudiants de même note peuvent donc être inversés. Si tu dois trier des enregistrements par un champ puis par un autre, ou afficher des ex æquo dans l'ordre d'inscription, la sélection est le mauvais outil : prends insertion ou fusion.

Quand même l'utiliser

Quand une écriture coûte cher : mémoire flash, EEPROM, registre matériel. La sélection minimise le nombre de déplacements (au plus n−1 échanges) au prix de beaucoup de lectures. C'est le seul des cinq tris de cette page qui a un argument sérieux dans ce cas.

06
fusion · n log n

Tri fusion : diviser, puis fusionner

On coupe le tableau en deux, on trie chaque moitié par le même procédé, puis on fusionne les deux moitiés triées en un seul balayage. C'est le tri qui garantit n log n dans tous les cas.

À retenir

Deux piles de copies déjà triées sur la table. Tu regardes la première carte de chaque pile, tu prends la plus petite, tu la poses sur la pile de sortie. Tu répètes. Quand une pile est vide, tu verses le reste de l'autre. Aucune comparaison inutile, aucun retour en arrière.

tri-fusion.c
/* fusionne t[g..m-1] et t[m..d-1], déjà triés, dans t[g..d-1] */
static void fusion(int16_t t[], int16_t tmp[], size_t g, size_t m, size_t d)
{
    size_t i = g, j = m, k = g;

    while (i < m && j < d) {
        if (t[j] < t[i]) {              /* strict : la gauche gagne les égalités */
            tmp[k++] = t[j++];
        } else {
            tmp[k++] = t[i++];
        }
    }
    while (i < m) { tmp[k++] = t[i++]; }   /* reste de la gauche */
    while (j < d) { tmp[k++] = t[j++]; }   /* reste de la droite */

    for (size_t p = g; p < d; p++) {
        t[p] = tmp[p];                 /* on recopie dans le tableau          */
    }
}

static void triFusionRec(int16_t t[], int16_t tmp[], size_t g, size_t d)
{
    if (d - g < 2u) {                  /* 0 ou 1 élément : déjà trié          */
        return;
    }
    size_t m = g + (d - g) / 2u;
    triFusionRec(t, tmp, g, m);
    triFusionRec(t, tmp, m, d);
    fusion(t, tmp, g, m, d);
}

void triFusion(int16_t t[], size_t n, int16_t tmp[])
{
    triFusionRec(t, tmp, 0u, n);       /* tmp : n cases, O(n) mémoire          */
}

Les barres bleues et vertes d'eau sont les deux moitiés en cours de fusion ; la ligne du bas montre le tampon tmp qui se remplit. Une fois le tampon complet, on le recopie dans le tableau : c'est le prix de la fusion.

Ce que garantit la fusion
  • O(n log n) dans tous les cas : le découpage est toujours en deux moitiés égales, le nombre de niveaux vaut ⌈log₂ n⌉.
  • Stable si, en cas d'égalité, on prend la gauche d'abord — c'est le rôle du < strict.
  • Pas en place : n cases auxiliaires, soit O(n) mémoire.
  • Pas adaptatif : un tableau déjà trié passe par les mêmes fusions (on peut ajouter un test, mais ce n'est plus l'algorithme du cours).
Combien de niveaux ?

Pour 7 éléments, ⌈log₂ 7⌉ = 3 niveaux de fusion. Pour 1 000 éléments, 10 niveaux ; pour 1 000 000, 20 niveaux. C'est cette croissance logarithmique qui rend la fusion imbattable sur les gros tableaux, alors que le tri à bulles aurait besoin de 500 milliards de comparaisons pour un million d'éléments.

Les trois fautes classiques de la fusion
  • Oublier de recopier le tampon dans le tableau : le résultat est juste dans tmp, pas dans t.
  • Utiliser ≤ au lieu de < dans la comparaison : la fusion devient instable, deux clés égales changent d'ordre.
  • Oublier le reste d'une moitié après la boucle principale : les éléments restants ne sont jamais écrits.
Le lien avec les listes chaînées

La fusion est le tri naturel d'une liste chaînée : on coupe la liste en deux, on trie chaque moitié, puis on relie les nœuds dans le bon ordre. Avantage : la fusion de deux listes se fait en O(1) mémoire, sans tampon, puisqu'il suffit de réarranger les liens. C'est exactement le genre de code du chapitre 3.

07
rapide · pivot

Tri rapide : un pivot, deux zones, deux récursions

On choisit un pivot, on range la zone en deux parts — plus petit à gauche, plus grand ou égal à droite — puis on trie chaque part par le même procédé. En moyenne le plus rapide des cinq ; au pire, le plus lent.

À retenir

Tu prends une valeur au hasard, disons le dernier élément, et tu fais deux tas : « plus petit que lui » et « plus grand ou égal ». Le pivot se retrouve alors à sa place définitive, sans avoir trié le reste. Il ne reste plus qu'à faire pareil dans chaque tas. Chaque pivot bien placé réduit le problème.

tri-rapide.c
/* partition de Lomuto : pivot = dernier élément, renvoie sa position finale */
static size_t partition(int16_t t[], size_t g, size_t d)
{
    int16_t pivot = t[d];
    size_t i = g;                      /* frontière : [g..i-1] < pivot        */

    for (size_t j = g; j < d; j++) {
        if (t[j] < pivot) {
            int16_t tmp = t[i];
            t[i] = t[j];
            t[j] = tmp;
            i++;
        }
    }
    int16_t tmp = t[i];                /* le pivot va à sa place définitive   */
    t[i] = t[d];
    t[d] = tmp;

    return i;
}

static void triRapideRec(int16_t t[], size_t g, size_t d)
{
    if (d <= g) {                      /* 0 ou 1 élément                      */
        return;
    }
    size_t p = partition(t, g, d);

    if (p > g) {                       /* évite g - 1 quand p == 0            */
        triRapideRec(t, g, p - 1u);
    }
    triRapideRec(t, p + 1u, d);
}

void triRapide(int16_t t[], size_t n)
{
    if (n > 1u) {
        triRapideRec(t, 0u, n - 1u);
    }
}

Suis le violet : le pivot est le dernier élément de la zone courante. Quand la partition se termine, il passe à sa position définitive (vert) et la zone est coupée en deux. Les zones déjà réglées s'éteignent, la récursion continue sur les autres.

Les trois complexités
  • Meilleur / moyen : O(n log n), environ 1,39 n log₂ n comparaisons en moyenne avec un pivot aléatoire.
  • Pire : O(n²), quand chaque partition ne sépare qu'un seul élément — tableau déjà trié avec pivot en dernière position, ou beaucoup de clés égales.
  • Mémoire : O(log n) en moyenne pour la pile de récursion, O(n) au pire. En place au sens strict du terme (pas de tableau auxiliaire).
  • Pas stable : les échanges font sauter les éléments par-dessus la zone.
Le pire cas est le cas le plus fréquent

Avec le pivot en dernière position, un tableau déjà trié est le pire des cas : chaque partition ne place qu'un élément, et il faut n niveaux de récursion. Sur sept éléments triés, cela fait 21 comparaisons et une profondeur de 7 au lieu de 3. Sur un fichier de 100 000 lignes déjà trié, la pile déborde. C'est le piège numéro un du chapitre.

Choisir un meilleur pivot
  • Milieu de la zone, ou médiane de trois (premier, milieu, dernier) : le cas trié redevient n log n.
  • Aléatoire : pas de cas pathologique systématique, mais un générateur à appeler et un résultat non déterministe.
  • Partition à trois zones (plus petit / égal / plus grand) quand il y a beaucoup de doublons : Lomuto dégénère, Hoare ou le « Dutch flag » non.
  • Récursion sur le plus petit côté d'abord, puis boucle sur l'autre : la pile reste en O(log n) même au pire.
Pourquoi p > g avant p - 1u

p et g sont des size_t, donc non signés. Si p == 0, l'expression p - 1u ne vaut pas −1 : elle vaut un nombre énorme, et l'appel récursif lit hors du tableau. Le test if (p > g) est la protection ; if (d <= g) en tête de fonction protège l'autre côté. Ces deux tests sont la différence entre un tri qui marche et un plantage aléatoire.

Comment choisir, en quatre questions

Il n'y a pas de « meilleur tri ». Il y a un tri adapté à trois contraintes : la taille des données, l'ordre déjà présent, et ce que coûte une écriture. Pose les questions dans cet ordre.

La réponse de l'ingénieur

Dans un vrai programme, on n'écrit pas ces tris : on appelle qsort (C) ou une fonction de bibliothèque, qui combine plusieurs algorithmes et choisit le meilleur selon la taille. Le cours demande de les écrire pour comprendre ce que la bibliothèque cache : les comparaisons, les écritures, la récursion et les garanties.

Le mauvais réflexe

« C'est presque trié, donc le tri rapide va être très rapide. » Avec un pivot en dernière position, c'est exactement l'inverse : un tableau presque trié produit des partitions déséquilibrées, donc une récursion profonde et un coût quadratique. Sur des données déjà ordonnées, prends insertion ou fusion.

Aucun des cinq ne réunit tout

Aucun des cinq tris de la fiche n'est à la fois stable, en place et garanti en n log n. La fusion est stable et garantie mais prend de la mémoire ; le rapide est en place mais ni stable ni garanti ; l'insertion est stable et en place mais quadratique. Des tris qui réunissent les trois existent (tri par blocs, block sort), mais ils sont nettement plus complexes et hors du cours.

bibliothèque · pointeur de fonction

qsort : trier n'importe quoi avec un comparateur

La bibliothèque standard du C ne sait pas trier des int16_t, des structures ou des chaînes : elle sait trier des octets et appeler une fonction de comparaison que tu fournis. Le tri devient générique parce que le critère est un pointeur de fonction.

qsort-int.c
#include <stdlib.h>

/* renvoie négatif, nul ou positif : jamais la différence brute */
int cmpInt16(const void *a, const void *b)
{
    int16_t x = *(const int16_t *)a;
    int16_t y = *(const int16_t *)b;

    return (x > y) - (x < y);          /* -1, 0 ou +1, sans dépassement */
}

int16_t t[7] = {5, 1, 4, 2, 8, 7, 3};
qsort(t, 7, sizeof t[0], cmpInt16);    /* t vaut 1 2 3 4 5 7 8 */
Ce que le comparateur doit renvoyer
valeursensconséquence
< 0a avant ba est placé avant
0égaux pour ce critèrel'ordre entre eux n'est pas garanti (qsort n'est pas stable)
> 0a après ba est placé après

Avec une structure, le même mécanisme s'applique : on convertit les void * vers le type réel, puis on compare le champ voulu.

qsort-struct.c
typedef struct {
    char nom[32];
    int  age;
} Etudiant;

int cmpAge(const void *a, const void *b)
{
    const Etudiant *x = a;             /* conversion implicite depuis void * */
    const Etudiant *y = b;

    return (x->age > y->age) - (x->age < y->age);
}

qsort(etudiants, n, sizeof etudiants[0], cmpAge);
Le comparateur qui plante une fois sur mille

return *(int *)a - *(int *)b; a l'air correct et casse sur les grandes valeurs : si a vaut INT_MAX et b vaut −1, la différence déborde d'un int — comportement indéfini. Écris toujours (x > y) - (x < y), qui vaut exactement −1, 0 ou +1, ou compare explicitement. Même piège avec strcmp : son résultat n'a pas besoin d'être −1 ou 1, seulement négatif, nul ou positif.

Les deux garanties de qsort

Pas stable : la norme C ne promet rien sur l'ordre des éléments égaux ; une implémentation peut utiliser un tri rapide, une autre un tri fusion. Aucune complexité garantie : la norme ne fixe pas de borne, et les implémentations courantes sont en O(n log n) en moyenne avec un pire cas O(n²) possible. Si tu as besoin de stabilité ou d'une borne garantie, trie avec fusion, ou trie sur un critère total (clé + rang d'arrivée).

Le tri générique du cours

C'est exactement le mécanisme de l'exercice 1.11 : une fonction de tri qui reçoit le tableau, la taille, et un pointeur vers la comparaison. On peut même choisir l'algorithme à l'exécution avec un tableau de pointeurs de fonction :

typedef void (*Tri_t)(int16_t t[], size_t n);

static const Tri_t tris[] = { triInsertion, triSelection, triRapide };
tris[0](t, n);   /* le tri est choisi à l'exécution */

Le jeu de tests qui attrape tout

Six tableaux suffisent à démasquer presque toutes les erreurs : vide (n = 0), un élément (n = 1), deux éléments inversés, déjà trié, ordre inverse, avec doublons (3 3 1 1 2 2 3 1). Le tableau d'un élément, et le tableau vide

Pour le tri rapide, triRapideRec(t, 0u, n - 1u) avec n == 0 calcule n − 1u sur un size_t : le résultat n'est pas −1 mais un nombre gigantesque. La garde if (n > 1u) n'est pas décorative. Mémo final et checklist

Tout ce qui doit rester après la dernière relecture, sur une page.

Les cinq complexités

tripiremém.
bullesn²1
insertionn²1
sélectionn²1
fusionn log nn
rapiden²log n

Stable / en place / adaptatif

  • Stables : bulles, insertion, fusion.
  • Pas stables : sélection, rapide.
  • En place : bulles, insertion, sélection, rapide.
  • Pas en place : fusion (n cases).
  • Adaptatifs : bulles, insertion.

Les formules

  • Inversions = échanges de voisins.
  • Pire cas quadratique : n(n−1)/2.
  • Borne des comparaisons : log₂(n!) ≈ n log₂ n − 1,44 n.
  • Fusion : ⌈log₂ n⌉ niveaux, ≤ n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1 comparaisons.
  • Coût du cours : ct = P(4N−2)t + 5It.

Une phrase par algorithme

  • Bulles : le plus grand remonte, on s'arrête si une passe n'échange rien.
  • Insertion : on insère une clé dans un préfixe trié en décalant.
  • Sélection : on cherche le minimum, un échange par passe.
  • Fusion : diviser en deux, fusionner deux suites triées.
  • Rapide : partitionner autour d'un pivot, récurser des deux côtés.

Les invariants

  • Bulles : après la passe k, les k dernières cases sont définitives.
  • Insertion : les i premiers éléments sont triés.
  • Sélection : les i premiers sont les i plus petits, triés.
  • Fusion : deux moitiés triées, deux index qui avancent.
  • Rapide : le pivot est à sa place définitive après la partition.

Checklist

  • Les bornes : i < n, j > 0, d − g < 2.
  • L'échange passe par un temporaire.
  • s = 0 au début de chaque passe.
  • size_t : jamais n − 1 sans garde.
  • Testé sur 0, 1, 2 éléments, trié, inverse, doublons.
  • Stabilité : comparaison stricte, gauche d'abord.
  • Complexités et mémoire récitées sans hésiter.
Le contrôle final, en trois lignes

Sur le témoin, chaque tri doit rendre 1 2 3 4 5 7 8. Le nombre d'échanges de voisins doit valoir 9 (les inversions). Et le tri doit rester correct sur un tableau vide, un tableau d'un élément et un tableau de doublons. Si ces trois contrôles passent, l'implémentation est saine.

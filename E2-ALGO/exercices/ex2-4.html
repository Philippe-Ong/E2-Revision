Entrées/sorties utilisateur

Lire deux flottants au clavier avec une fonction d'invite, gérer les erreurs et afficher la somme au format demandé.

exercice 2.4 scanf · fgets · validation · somme · erreurs de saisie théorie : Entrées/sorties et fichiers
01
énoncé

Ce que demande l’exercice

L'application lit deux nombres à virgule flottante saisis sur la console et affiche leur somme sur celle-ci.

L'énoncé montre les invites « Please enter first operand: » et « Please enter second operand: », puis « Result of 1.20000 + 3.45000 = 4.65000 ».

La lecture est d'abord dans main avec scanf, puis déplacée dans une fonction qui reçoit le texte d'invite et retourne la valeur convertie ; l'étape e ajoute le traitement d'erreur.

De la console au résultat
La saisie passe par le tampon d'entrée, puis scanf ou fgets + strtod la convertit avant l'affichage de la somme.
02
théorie nécessaire

Les notions à mobiliser

scanf renvoie un compte d'affectations

scanf("%lf", &v) renvoie 1 en cas de succès, 0 si le texte ne correspond pas au format, EOF avant toute conversion. Le test correct est != 1 ; feof n'aide pas ici.

scanf ou fgets

scanf laisse dans le tampon ce qu'il n'a pas consommé. fgets lit une ligne bornée et garde le '\n' ; avec strtod, il refuse « 1.2abc ». L'énoncé impose scanf, fgets est la variante robuste.

Invite et tampon

stdout est tamponné : une invite sans '\n' peut rester invisible. fflush(stdout) la force. Après un échec, la saisie fautive reste dans le tampon : sans boucle getchar jusqu'à '\n' ou EOF, la lecture suivante échoue aussi.

Format de sortie

L'énoncé affiche cinq décimales : %.5f. Avec %f, on obtient six décimales (1.200000). La somme 1.2 + 3.45 s'affiche 4.65000.

03
méthode

Comment procéder

  1. Écrire lireOperande(const char *invite, double *valeur), qui affiche l'invite et lit un double.
  2. Appeler fflush(stdout) avant la lecture.
  3. Tester le retour de scanf : != 1 signale l'échec.
  4. Vider la ligne avec getchar jusqu'à '\n' ou EOF, puis retourner 0.
  5. Dans main, deux appels, sortie sur stderr si l'un échoue, affichage avec %.5f.
04
application

Application à l’énoncé

exemple.cC11
#include <stdio.h>
#include <stdlib.h>

/* 1 si la lecture a reussi, 0 sinon */
static int lireOperande(const char *invite, double *valeur)
{
    printf("%s", invite);
    fflush(stdout);                 /* l'invite n'a pas de '\n' */
    if (scanf("%lf", valeur) != 1) {
        int c;
        while ((c = getchar()) != '\n' && c != EOF) { }  /* vider la ligne */
        return 0;
    }
    return 1;
}

int main(void)
{
    double a = 0.0;
    double b = 0.0;
    if (!lireOperande("Please enter first operand: ", &a)
        || !lireOperande("Please enter second operand: ", &b)) {
        fprintf(stderr, "Valeur invalide.\n");
        return 1;
    }
    printf("Result of %.5f + %.5f = %.5f\n", a, b, a + b);
    return 0;
}

Le programme reproduit la console de l'énoncé ; une saisie invalide part sur stderr et retourne 1.

Résultat. 1.20000 + 3.45000 = 4.65000 ; sur « abc », le programme affiche « Valeur invalide. » sur stderr et retourne 1.
05
erreurs fréquentes

Les pièges

À vérifier
  • Tester scanf(...) == 0 : EOF (−1) passe pour un succès ; il faut != 1.
  • Oublier fflush(stdout) : l'invite reste dans le tampon et le programme semble bloqué.
  • Ne pas vider le tampon après une erreur : la lecture suivante échoue sur les mêmes caractères.
  • Utiliser %f au lieu de %.5f : la sortie ne correspond plus à l'énoncé.

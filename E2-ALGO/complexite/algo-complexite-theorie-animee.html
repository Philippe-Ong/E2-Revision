Exercices 1.21.5
01
l'idée

Compter les opérations, pas les secondes

Le coût d'un algorithme, c'est ce qu'il demande pour une taille de données N : un nombre d'opérations élémentaires pour le temps, un nombre de cases pour la mémoire. On le compte ; on ne le chronomètre pas.

La raison est simple : un temps mesuré dépend de la machine, de sa charge, du compilateur et du système. Le même programme s'exécute deux fois plus vite sur un processeur deux fois plus rapide, sans qu'une seule ligne ait changé. Un compte d'opérations, lui, ne bouge pas : il ne dépend que de l'algorithme et de N.

À retenir

Un processeur deux fois plus rapide divise tous les temps par deux ; il ne change aucune classe de complexité. C'est la croissance en fonction de N, pas la vitesse d'une machine, qui décide si un algorithme reste utilisable.

Le cours formalise la chose avec la machine de Turing : une bande infinie de cases, une tête de lecture/écriture et une table de transitions. Dans ce modèle, les deux coûts se définissent sans ambiguïté :

  • Coût en temps : le nombre de transitions nécessaires pour terminer l'algorithme.
  • Coût en mémoire : le nombre de cases de la bande utilisées pendant l'exécution.

La thèse de Church et Turing affirme qu'une fonction est calculable par algorithme si et seulement si une machine de Turing la calcule. La conséquence pratique est directe : on peut compter les opérations d'un programme C comme on compterait les transitions de la machine.

La règle

Les deux coûts s'écrivent ct(N) pour le temps et cs(N) pour l'espace. On choisit une opération témoin — l'addition d'une somme, la comparaison d'un tri, l'incrément d'un compteur — et on compte combien de fois elle s'exécute quand N varie.

Ce que l'analyse apporte, et que la mesure ne donne pas :

Le piège

Un algorithme O(N) peut être plus lent qu'un O(N²) pour de petites valeurs de N : la classe décrit la croissance quand N grandit, pas le temps à N = 10. Les constantes décident pour les petits N, la classe décide pour les grands.

02
le comptage

Une boucle de N tours coûte 4Nt, plus l'initialisation

L'exemple 1 du cours est la somme d'un tableau. Une initialisation, puis quatre opérations par tour : incrémenter le compteur, lire table[i], additionner, affecter. Si chaque opération coûte t, le total est (1 + 4N)t.

somme.c
int64_t somme(int64_t table[], size_t n)
{
    int64_t s = 0;                  /* 1 fois : 1t */
    for (size_t i = 1; i <= n; i++) {
        /* 4 opérations par tour : incrément de i,
           accès à table[i], addition, affectation */
        s = s + table[i];
    }
    return s;
}

Le compte est indépendant des valeurs du tableau : que les nombres soient triés ou mélangés, la boucle lit toujours N cases. C'est un coût linéaire.

La formule

ct(N) = t + 4Nt = (1 + 4N)t. Pour N = 10 : 41t ; pour N = 100 : 401t ; pour N = 1 000 : 4 001t. Le coût exact garde le 1, le 4 et le t ; la classe O(N) les supprime.

Le coût exact et la classe

41t est le coût exact pour N = 10 ; O(N) est sa classe. Si l'énoncé demande le coût, il faut garder t et le terme constant ; s'il demande la complexité, on ne garde que le terme dominant.

Le piège

Écrire O(4N + 1) n'est pas faux, mais inutile : O(4N + 1) = O(N). Les constantes multiplicatives et les termes plus petits que le dominant disparaissent de la notation.

03
un algorithme complet

Le tri à bulles : 45 comparaisons pour N = 10

Le tri à bulles est l'exemple 2 du cours. À chaque passe, on compare les voisins et on échange les paires inversées ; le plus grand monte à la fin comme une bulle. On s'arrête quand une passe n'échange plus rien.

tri-bulles.pseudo
repeat
  s := 0
  for i is varying from 2 to N do:
    if (A[i] < A[i-1]) then
      swap(A[i], A[i-1])
      s := s + 1
    end if
  end for
until s = 0

Deux quantités gouvernent le coût : le nombre de passes P et le nombre de permutations I. Une permutation est un échange de deux voisins ; elle corrige exactement une inversion, c'est-à-dire une paire i < j avec A[i] > A[j]. Le nombre total de permutations est donc le nombre d'inversions du tableau de départ.

Pour N = 10, la version classique réduit la borne de la boucle interne d'une unité à chaque passe, puisque le plus grand élément est déjà en place : la première passe fait 9 comparaisons, la suivante 8, et ainsi de suite jusqu'à 1 (le pseudo-code ci-dessus garde, lui, i = 2 … N ; voir la note sur les deux comptages). D'où :

Les comparaisons

9 + 8 + … + 1 = 45 comparaisons pour N = 10, soit N(N − 1) / 2 en général. C'est O(N²) : doubler N quadruple le nombre de comparaisons.

Sur la série de l'exercice 1.5 — 28 3 45 1 5 17 33 32 42 2 — voici le détail passe par passe. Le tableau se trie en 9 passes et 20 permutations :

Le cours demande aussi le coût en t, avec une convention au même grain que l'exemple 1 : s := 0 coûte 1t, chaque tour de boucle coûte 4t (incrément, deux accès, comparaison), et until coûte 1t. Une passe vaut donc 4(N − 1) + 1 + 1 = (4N − 2)t.

La convention du cours

ct = P (4N − 2) t + 5 I t, avec P passes et I permutations. Un échange coûte 3t (hypothèse de la diapo) plus 2t pour s := s + 1, d'où 5t par permutation.

Deux comptages, une même classe

Le total 9 + 8 + … + 1 = 45 suppose la borne qui rétrécit. Le pseudo-code du cours garde i = 2 … N à chaque passe : il refait alors 9 comparaisons par passe, soit 81 pour la série de 9 passes. Pour l'ordre inverse, la même convention donne 9 passes (10 avec la borne fixe). Les permutations et la classe O(N²) ne changent pas ; seule la convention de comptage change, comme pour les constantes de la formule en t.

Deux erreurs classiques

N passes ≠ N comparaisons : chaque passe fait N − 1 comparaisons. Et il faut remettre s à zéro au début de chaque passe : sinon le compteur garde les échanges de la passe précédente et la boucle ne s'arrête jamais.

Combien de permutations et de passes pour 5 4 3 2 1 ?
10 permutations, car chaque paire est une inversion (5 × 4 / 2), et 5 passes avec le pseudo-code du cours. C'est l'ordre inverse : le coût maximal en échanges.
04
la notation

Big-O : garder le terme dominant

La notation O compare des fonctions quand N grandit. Elle ne dit pas « ce programme prend tant de secondes » : elle dit « à partir d'un certain N, ce coût reste sous un multiple de g(N) ».

La définition

f(N) = O(g(N)) s'il existe une constante c > 0 et un seuil N0 tels que, pour tout N ≥ N0, 0 ≤ f(N) ≤ c · g(N). g est une borne supérieure de f à partir de N0.

En pratique, on ne cherche pas c et N0 : on garde le terme qui croît le plus vite et on supprime tout le reste. Les constantes multiplicatives disparaissent aussi.

Le cours utilise O ; les deux notations complémentaires précisent l'encadrement. Ω donne une borne inférieure, Θ une borne des deux côtés :

O, Ω et Θ
notationinégalitésens
f = O(g)f(N) ≤ c · g(N)f ne croît pas plus vite que g

Le sens de « = »

f(N) = O(g(N)) se lit « f est un grand O de g ». Le signe égal n'est pas une égalité : O(N) désigne un ensemble de fonctions. On écrit 3N² + 5N + 7 = O(N²), et aussi N² = O(N³) — la borne supérieure n'est pas unique.

Le piège

O(g) est une borne supérieure : dire O(N²) ne prouve pas que l'algorithme est quadratique, seulement qu'il ne dépasse pas ce rythme. C'est Θ qui donne la croissance exacte. Et O(1) ne veut pas dire « une seule instruction » : cela veut dire « un nombre d'opérations qui ne dépend pas de N ».

05
les classes

Huit classes, de O(1) à O(n!)

Les algorithmes se rangent en un petit nombre de classes. Entre deux classes voisines, l'écart finit toujours par devenir plus grand que n'importe quelle constante : à N = 60, 2ⁿ µs font 365 siècles, alors que N² µs font 3,6 ms.

Le piège de la base

La base du logarithme ne change pas la classe : log₂ n = ln n / ln 2, et 1 / ln 2 est une constante. Donc O(log₂ n) = O(ln n) = O(log n). En revanche, O(log n) n'est pas O(1) : le logarithme grandit, lentement mais sans borne.

06
les cas

Meilleur, moyen, pire : la même fonction, trois coûts

Une complexité sans cas est incomplète. Le tri à bulles est O(N) sur un tableau déjà trié, O(N²) sur un tableau inversé, et O(N²) en moyenne. C'est le pire cas qui décide si l'algorithme tient à l'échelle.

Le meilleur cas vient de la sortie anticipée : si une passe ne fait aucun échange, le tableau est trié et la boucle s'arrête. Un tableau déjà trié ne coûte donc qu'une passe, soit 9 comparaisons et 0 échange pour N = 10.

Le lien avec le tri rapide

Le tri rapide (quicksort) est O(n log n) en moyenne et O(n²) dans le pire cas, quand le pivot choisi est systématiquement le plus petit ou le plus grand. La diapo 8 le classe en O(n log n) : c'est son comportement moyen, pas une garantie sur toutes les entrées.

Le piège

« En moyenne O(n log n) » ne protège pas du pire cas. Un algorithme peut être excellent sur des données aléatoires et quadratique sur une entrée déjà triée — c'est précisément le cas du tri rapide avec un mauvais choix de pivot.

Un tableau trié est-il toujours le meilleur cas du tri à bulles ?
Oui, avec la sortie anticipée : une passe suffit. Mais un tableau presque trié peut demander beaucoup de passes si un petit élément est resté à la fin : il ne recule que d'une case par passe (la « tortue »).
07
la récursion

Une récurrence se résout, puis se compte

Pour une fonction récursive, le coût en temps s'écrit comme une récurrence : le coût de n en fonction du coût de n − 1 (ou de deux appels plus petits). La résoudre donne la formule fermée, puis la classe.

Factorielle : un appel par valeur

factorielle.c
uint64_t factorialRecursion(uint32_t n)
{
    if (n <= 1u) {
        return 1u;                              /* cas de base       */
    }
    return (uint64_t)n * factorialRecursion(n - 1u);
}

Chaque appel fait un appel de plus, sans branche : T(n) = T(n − 1) + 1, avec T(1) = 1, donc T(n) = n. Le coût est O(n) et la pile monte à n trames. Pour 4!, quatre appels : fact(4), fact(3), fact(2), fact(1).

Hanoï : deux appels par niveau

hanoi.c
void toh(uint32_t disk, char source, char dest, char aux,
         uint32_t *pMoves)
{
    if (disk == 1u) {
        moveDisk(1u, source, dest, pMoves);          /* cas simple  */
    } else {
        toh(disk - 1u, source, aux, dest, pMoves);   /* vers l'aux  */
        moveDisk(disk, source, dest, pMoves);        /* le grand    */
        toh(disk - 1u, aux, dest, source, pMoves);   /* vers la fin */
    }
}

Pour déplacer n disques, il faut déplacer n − 1 disques deux fois, plus un coup : M(n) = 2 M(n − 1) + 1, avec M(1) = 1. La solution est M(n) = 2ⁿ − 1, donc O(2ⁿ). Pour 64 disques : 18 446 744 073 709 551 615 coups, soit environ 585 ans à un milliard de coups par seconde.

Fibonacci : l'arbre qui se répète

fibonacci.c
uint64_t fib(uint32_t n)
{
    if (n <= 1u) {
        return n;                               /* f(1) = 1, f(0) = 0 */
    }
    return fib(n - 1u) + fib(n - 2u);
}

La récurrence T(n) = T(n − 1) + T(n − 2) + 1 donne une croissance exponentielle, de l'ordre de φⁿ avec φ ≈ 1,618, donc O(2ⁿ). Le nombre d'appels explose : 15 pour fib(5), 177 pour fib(10), 21 891 pour fib(20). La cause est visible sur l'arbre : le même sous-problème est recalculé plusieurs fois.

Les trois récurrences à connaître
  • T(n) = T(n − 1) + 1 → n, soit O(n) : factorielle, somme récursive.
  • T(n) = 2 T(n − 1) + 1 → 2ⁿ − 1, soit O(2ⁿ) : Hanoï.
  • T(n) = T(n − 1) + T(n − 2) → croissance en φⁿ, soit O(2ⁿ) : Fibonacci naïve.
Le piège

Une récursion sans cas de base empile des trames jusqu'à épuiser la pile : le programme plante (stack overflow). Et une récurrence « qui a l'air linéaire » peut être exponentielle : Fibonacci appelle deux fonctions, pas une.

08
la mémoire

Le coût mémoire : trames, tableaux, allocations

Le temps n'est qu'un des deux coûts. Chaque appel récursif empile une trame, un tableau de N éléments occupe N cases, et un malloc réserve un bloc sur le tas jusqu'au free. Un algorithme qui n'utilise qu'un nombre constant de cases en plus est dit en place.

En place, ou pas

Le tri à bulles et le tri par insertion réordonnent le tableau sur place : O(1) cases en plus. Le tri fusion, lui, alloue un tableau auxiliaire de N cases : O(N) en mémoire. Même classe O(n log n) pour le temps, coût mémoire différent.

Le piège

« En place » ne veut pas dire « sans mémoire » : le tableau d'entrée occupe déjà N cases. Cela veut dire que l'algorithme n'ajoute qu'un nombre constant de cases. Et une récursion de profondeur N coûte O(N) en pile, même si elle ne déclare qu'une variable par appel.

Applications

La LUT de factorielle de l'exercice 1.2 échange de la mémoire contre du temps : 21 valeurs de 8 octets, soit 168 octets de données statiques, et une lecture en O(1) au lieu d'une boucle ou d'une récursion O(n).

09
la mesure

Mesurer pour vérifier, pas pour classer

La mesure ne remplace pas l'analyse, mais elle la contrôle : elle confirme qu'une implémentation a bien la croissance annoncée et elle révèle les constantes. Encore faut-il mesurer proprement — répéter, prendre une médiane et fixer le niveau d'optimisation.

mesure.c · extrait du banc
#include <stdint.h>
#include <stdio.h>
#include <time.h>

static uint64_t s_checksum;          /* empêche la suppression du calcul */

static double maintenant(void)
{
    return (double)clock() / CLOCKS_PER_SEC;    /* temps CPU */
}

int main(void)
{
    double const debut = maintenant();
    for (int tour = 0; tour < 200000; tour++) {
        for (uint32_t n = 0u; n <= 20u; n++) {
            s_checksum += factorialRecursion(n);
        }
    }
    double const duree = (maintenant() - debut)
                       / (200000.0 * 21.0);
    printf("%.3f ns par appel\n", duree * 1e9);
}
  • Répéter : une seule mesure ne veut rien dire. Le banc du guide fait 200 000 tours, puis 7 séries, et garde la médiane.
  • Utiliser le résultat : sans s_checksum, le compilateur peut supprimer la boucle à -O2 et le temps tombe à zéro.
  • Fixer les options : -O0 mesure le code tel qu'écrit, -O2 mesure ce que le compilateur en fait. Ce ne sont pas les mêmes constantes.
  • Ne pas comparer deux machines, deux systèmes ou deux charges : seul le même banc, sur la même machine, est comparable.

À -O2, gcc transforme la récursion en boucle et le temps rejoint celui de l'itération : la récursion n'est pas « lente » en soi, elle paie ses appels. La LUT reste devant, parce qu'elle ne calcule rien.

Ce qu'on peut conclure

Oui : comparer deux implémentations du même algorithme, vérifier qu'un tri de 2 000 éléments est environ quatre fois plus lent qu'un tri de 1 000, constater l'effet d'une optimisation.

Non : déduire une classe d'un temps isolé, comparer deux machines, ou conclure qu'un algorithme O(N²) est « rapide » parce qu'il l'est pour N = 100.

Le piège

clock() mesure le temps CPU, pas le temps écoulé, et sa résolution est grossière. Pour une opération de quelques nanosecondes, il faut répéter des milliers de fois et diviser, sinon on mesure le bruit. Un unique clock() autour d'un appel ne prouve rien.

Pourquoi la médiane plutôt que la moyenne des sept séries ?
Une série peut être perturbée par une autre tâche du système ou un changement de fréquence du processeur. La médiane ignore ces valeurs aberrantes ; la moyenne les laisserait tirer le résultat.
10
le choix

Choisir un algorithme selon N et le budget

À un pas de 1 µs, une seconde représente un million d'opérations. Ce budget suffit à un million d'éléments en O(N), mais à 1 000 seulement en O(N²) et à 19 en O(2ⁿ). C'est cela qui décide, pas l'élégance du code.

Les réflexes de choix
  • Petit N (moins de quelques centaines) : le plus simple suffit ; un O(N²) bien écrit passe.
  • Grand N (millions) : viser O(n log n) ou O(n) ; un O(N²) est éliminé d'avance.
  • Recherche répétée : trier une fois puis chercher en O(log n) bat un parcours linéaire répété.
  • Espace : si la mémoire est comptée, préférer un tri en place, même un peu plus lent.
  • Permutations : n! n'est utilisable que pour de très petits n ; 12! pas font déjà 8 minutes, 13! 1,7 heure.
Le tri, cas d'école

Le tri à bulles est O(N²) et le tri fusion O(n log n). Pour N = 1 000 000, le premier ferait de l'ordre de 10¹² comparaisons, le second environ 2·10⁷ : le rapport est de plusieurs ordres de grandeur. C'est pourquoi un cours commence par le tri à bulles — pour comprendre — et les bibliothèques offrent qsort.

Le piège

Ne pas confondre « 2ⁿ est petit pour n = 10 » (1 024) avec « 2ⁿ est utilisable » : à n = 40, 2⁴⁰ µs font 12,7 jours ; à n = 60, 365 siècles. La classe ne se juge pas sur les petites valeurs.

Le piège des boucles imbriquées

Deux boucles imbriquées ne font pas toujours N² tours. Si la borne interne dépend de l'extérieure, il faut sommer : Σi=0..N−1 i = N(N − 1) / 2, soit 45 pour N = 10 et non 100. La classe reste O(N²), mais le compte exact change.

Trois boucles imbriquées, chacune de 1 à N : combien de count++ pour N = 30 ?
N³ = 27 000. Pour N = 10 : 1 000 ; pour N = 20 : 8 000. Chaque niveau multiplie le nombre de tours par N.
Un algorithme fait 45 comparaisons pour 10 éléments. Est-il O(N²) ou O(N) ?
45 = 10 × 9 / 2 suit N(N − 1)/2 : c'est O(N²). Un coût linéaire donnerait de l'ordre de 10 comparaisons, pas 45. Un seul point ne suffit pas : il faut comparer plusieurs tailles.

À retenir

Trois questions suffisent pour traiter un coût : quelle opération témoin ? combien de fois s'exécute-t-elle en fonction de N ? quel terme domine ? Le temps et la mémoire se traitent séparément, et le pire cas est celui qui décide.

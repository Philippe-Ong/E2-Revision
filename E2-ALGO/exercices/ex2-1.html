Calculatrice en ligne de commande

Lire deux opérandes et un opérateur dans argv, les valider, puis calculer avec getResult.

exercice 2.1 argc/argv · strtod · validation · getResult · division par zéro théorie : Entrées/sorties et fichiers
01
énoncé

Ce que demande l’exercice

L'application reçoit trois arguments : Arg1, Op puis Arg2, avec Op parmi +, -, x et /.

L'énoncé demande main(int argc, char *argv[]), le contrôle du nombre d'arguments et un message d'usage par printf.

Les opérandes passent en double et l'opérateur en char ; une fonction dédiée valide les paramètres avant l'appel.

getResult reçoit les deux doubles et l'opérateur, calcule et retourne le résultat. La division par zéro est traitée avant l'appel, car getResult ne peut pas signaler d'erreur.

02
théorie nécessaire

Les notions à mobiliser

argc et argv

argc compte le programme : 4 pour trois arguments. argv[0] est son nom, argv[1] à argv[argc−1] les paramètres, argv[argc] vaut NULL. Lire argv[3] sans vérifier argc lit un pointeur inexistant.

atof ou strtod

L'énoncé cite atof(), qui renvoie 0.0 quand rien n'est convertible : « 0 » et « abc » deviennent indistinguables. strtod(texte, &fin) donne la fin de conversion ; la validation exige fin != texte et *fin == '\0'.

getResult et division par zéro

getResult retourne un double : elle ne signale pas d'erreur. Le test b == 0.0 pour / se fait donc dans main. En C, 1.0 / 0.0 ne plante pas : il produit inf ; 0.0 / 0.0 produit nan.

Un opérateur d'un seul caractère

strlen(argv[2]) != 1 rejette « xx » et la chaîne vide. On compare ensuite argv[2][0] à '+', '-', 'x' et '/' dans un switch. L'opérateur % n'est pas demandé et tombe dans l'usage.

03
méthode

Comment procéder

  1. Déclarer int main(int argc, char *argv[]).
  2. Vérifier argc == 4 et strlen(argv[2]) == 1 ; sinon afficher l'usage et retourner 1.
  3. Convertir argv[1] et argv[3] avec strtod en contrôlant la fin de conversion.
  4. Refuser un opérateur inconnu et la division par un diviseur nul.
  5. Appeler getResult, afficher avec %g et vérifier le code de retour des cas d'erreur.
04
application

Application à l’énoncé

exemple.cC11
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static int parametresValides(int argc, char *argv[])
{
    if (argc != 4) { return 0; }
    if (strlen(argv[2]) != 1) { return 0; }
    char op = argv[2][0];
    return (op == '+' || op == '-' || op == 'x' || op == '/');
}

static int nombreValide(const char *texte, double *valeur)
{
    char *fin = NULL;
    *valeur = strtod(texte, &fin);
    return (fin != texte && *fin == '\0');
}

static double getResult(double a, char op, double b)
{
    switch (op) {
        case '+': return a + b;
        case '-': return a - b;
        case 'x': return a * b;
        case '/': return a / b;
        default:  return 0.0;
    }
}

int main(int argc, char *argv[])
{
    double a = 0.0, b = 0.0;
    if (!parametresValides(argc, argv)
        || !nombreValide(argv[1], &a)
        || !nombreValide(argv[3], &b)) {
        printf("Usage : %s <Arg1> <Op> <Arg2>   (Op = + - x /)\n", argv[0]);
        return 1;
    }
    if (argv[2][0] == '/' && b == 0.0) {
        printf("Division par zero.\n");
        return 1;
    }
    double r = getResult(a, argv[2][0], b);
    printf("%g %c %g = %g\n", a, argv[2][0], b, r);
    return 0;
}

La validation précède le calcul : parametresValides contrôle argc et l'opérateur, nombreValide exige que toute la chaîne soit consommée.

05
erreurs fréquentes

Les pièges

À vérifier
  • Lire argv[3] sans vérifier argc : pointeur inexistant ou valeur aléatoire.
  • atof sans contrôle : « abc » donne 0.0 et le calcul se fait sur zéro.
  • Laisser getResult diviser par zéro : le résultat vaut inf, sans message.
  • Comparer argv[2] == "+" compare des adresses ; il faut argv[2][0] ou strcmp.
